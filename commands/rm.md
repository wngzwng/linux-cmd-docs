# rm：从 `-i` 安全删除到 `-rf` 的杀伤半径，把删文件变成可控操作

> 每个人都敲过 `rm`。但大多数人没认真想过：`rm` 做了什么？删了的文件能恢复吗？`-rf` 里的 `f` 和 `r` 各自是什么含义？以及——怎样防止灾难性的误删？

## 一、你会遇到的场景

某天你清理 `node_modules`，手滑多打了一个空格：

```bash
rm -rf / tmp/node_modules     # 注意 / 后面的空格——这是一条能把根分区删光的命令
```

类似的事故每天都在发生。"我只是想删一个目录"的下一秒变成了"系统不启动了"。

**这就是 rm 的核心价值：删除文件/目录——它是不可逆操作，使用前必须理解每一个选项的含义。**

> ⚠️ 本文遵循安全铁律：**涉及 destructive 操作的每个示例，都先展示安全预览步骤，再展示执行步骤。**

## 二、语法骨架

```
rm  [选项]  文件...
    ──┬──   ──┬──
     怎么删    删什么
```

属于**骨架模式 C**：`动作 + 目标`。极其简单——复杂的是选项组合和它们的安全含义。

## 三、核心能力逐轴拆解

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 范围轴 | 删文件还是目录？ | 默认只删文件、`-r`(递归删目录)、`-d`(删空目录) |
| 确认轴 | 要不要我确认？ | 默认(部分确认)、`-i`(每个都问)、`-I`(超过3个或递归时问一次)、`-f`(不确认) |
| 反馈轴 | 删的时候告诉我吗？ | 默认(无)、`-v`(逐个打印删了什么) |

---

### 轴 1：范围轴——"删什么类型？"

```bash
# 删单个文件
rm file.txt

# 删多个文件
rm file1.txt file2.txt file3.txt

# 删整个目录树（⚠️ 危险！）
# 第一步：先看看目录里有什么
ls -R node_modules/ | head

# 第二步：确认无误后执行
rm -r node_modules/
```

> ⚠️ **`-r` 和 `-rf` 的区别：** `-r` 删目录时遇到写保护的文件会提示确认；`-rf` 静默跳过一切提示。`-f` 让你删得更快——也让灾难发生得更快。

---

### 轴 2：确认轴——"要不要我确认？"

```bash
# -i：每个文件删除前都确认（最安全，但很烦）
rm -i *.log

# -I：只在超过 3 个文件或递归删目录时问一次（更实用的选择）
rm -I *.tmp

# -f：不确认，不报错（如果文件不存在也不报）——最危险
rm -f *.log
```

> 💡 把 `alias rm='rm -I'` 写进 `.bashrc` 是防止手滑的最低成本方案。`-I` 不像 `-i` 那样烦人（不会每个文件都问），但在有风险时（目录递归、批量删除）仍然会拦截你。

---

### 轴 3：反馈轴——"让我看看删了什么"

```bash
# -v：打印每个被删的文件名（事后审计用）
rm -v *.log
```

---

## 四、安全习惯——你必须养成的五条

```bash
# 习惯 1：删除之前先 ls 预览
ls *.log                # 先看看匹配了哪些文件
rm *.log                # 确认无误再删

# 习惯 2：不确定时先 ls，不用 * 通配符
ls /some/path/*.log     # 通配符展开后是什么？先看一眼

# 习惯 3：用 trash-cli 代替 rm（移到回收站，可恢复）
brew install trash-cli    # macOS
trash *.log

# 习惯 4：alias rm='rm -I'（防手滑）
# 加到 ~/.bashrc

# 习惯 5：在脚本里用 rm 时，永远用绝对路径 + 变量检查
DESTROY_DIR="/var/tmp/build-$(date +%s)"
mkdir -p "$DESTROY_DIR" && echo "created $DESTROY_DIR"
# ... 用完之后 ...
ls "$DESTROY_DIR" && rm -rf "$DESTROY_DIR"
# 注：先 ls 确认路径存在且正确，再 rm
```

## 五、踩坑清单

- **坑一：`rm -rf /` 是真实存在的灾难路径** → 永远不会写 `rm -rf /` 或 `rm -rf /*`。多打一个空格可能毁掉整个系统。用 `rm -rf ./dirname`（加 `./` 前缀至少防止路径为空的情况）。
- **坑二：`rm *.log` 在没有 .log 文件时，bash 可能把字面量 `*.log` 传给 rm** → 取决于 shell 的 `nullglob` 设置。在脚本里先用 `shopt -s nullglob`（bash）。
- **坑三：`rm` 删的文件不是"覆盖写零"，而是 unlink** → 数据还在磁盘上（直到被新数据覆盖）。需要安全删除用 `shred`。
- **坑四：`-f` 掩盖错误** → `rm -f nonexistent` 不会报错，脚本里如果路径写错了你可能完全不知道。调试阶段不加 `-f`。
- **坑五：root 用户删除的文件，普通用户的回收站工具（trash-cli）可能无法恢复** → root 的删除更不可逆，小心。

## 六、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 日常文件删除 | `trash` / `gvfs-trash` | 移到回收站，可恢复 |
| 安全删除（防恢复） | `shred` | 多次覆写随机数据 |
| 批量重命名而非删除 | `rename` / `mmv` | 你其实不需要删——只是格式不对 |
| 找大文件然后决定删不删 | `find ... -size +100M` | 先找再删，不要盲目 `rm -rf *` |

---

> **核心观点：** `rm` 不需要"学"——它只有三个字母和三个选项。需要建立的是**安全肌肉记忆**：**先 ls 预览 → 再 rm 执行**。以及把 `alias rm='rm -I'` 写进配置文件。这两个习惯能挡住 90% 的误删事故。
