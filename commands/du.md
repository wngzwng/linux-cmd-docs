# 为什么 du 很强，但大多数人只会 `du -sh *`？

> 磁盘满了，你敲 `du -sh *` 一层层挖下去，像一个考古学家。其实 du 是一个磁盘使用分析器——你可以精确控制深度、排除目录、找到真正的大户，而不是一层层手动翻。

## 一、你会遇到的场景

某天根分区 95%。你需要快速定位：哪个目录在吃磁盘？

新手的做法：`du -sh /*` → 看到 `/var` 很大 → `du -sh /var/*` → 看到 `/var/log` 很大 → `du -sh /var/log/*`……一层一层，像剥洋葱。

而真正理解 du 的人：

```bash
du -h -d 2 / | sort -rh | head -20
```

一次看到根目录下 2 层深度的所有目录大小，按从大到小排列。20 行里找到元凶。

**这就是 du 的核心价值：显示目录/文件的磁盘占用——控制深度、控制粒度、按需汇总。** du = **d**isk **u**sage。

## 二、语法骨架

```
du  [选项]  [文件/目录...]
    ──┬──   ────┬────
     展示控制    查什么
```

## 三、核心能力逐轴拆解

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 深度轴 | 展开几层？ | `-d N`(最多N层)、`-s`(只汇总)、默认(全部展开) |
| 格式轴 | 怎么看大小？ | `-h`(人类可读)、`-k`(KB)、`-m`(MB)、`-g`(GB) |
| 范围轴 | 看哪些文件？ | `-a`(含文件)、默认(只目录)、`-I`(排除模式) |
| 对比轴 | 真实大小还是磁盘占用？ | `-A`(apparent size，文件实际字节数)、默认(磁盘占用) |

---

### 轴 1：深度轴——"展开几层？"

```bash
# 只看当前目录的总大小（-s = summarize）
du -sh

# 只看 1 层深度的子目录大小
du -h -d 1

# 看 2 层深度（最实用的用法！）
du -h -d 2 /var | sort -rh | head
```

> 💡 `-d` 是 du 最被低估的选项。不用 `-d` 时 du 会列出所有子目录的所有层级——输出几千行。`-d 2` 给你一个"刚好的视角"。

---

### 轴 2：格式轴——"怎么看大小？"

```bash
# -h：人类可读（1.2G / 345M）
du -sh *

# -m：以 MB 为单位
du -sm *

# -k：以 KB 为单位
du -sk *

# 排序：按大小降序
du -sh * | sort -rh
```

---

### 轴 3：范围轴——"看哪些文件？"

```bash
# -a：包括文件（默认只显示目录汇总）
du -ah -d 1

# 只看特定模式的文件
du -sh *.log

# -I：排除匹配模式的文件/目录
du -sh -I '*.log' /var
```

---

### 轴 4：对比轴——"真实大小 vs 磁盘占用"

```bash
# -A：显示 apparent size（文件实际字节数）
du -shA sparsefile.bin   # 可能显示 10G

# 默认：显示磁盘占用（实际占了多少块）
du -sh sparsefile.bin     # 可能只显示 1M（稀疏文件）
```

> ⚠️ **`du` 默认显示的是磁盘占用，不是文件大小。** 稀疏文件（大部分是空洞数据，没实际写在磁盘上）的磁盘占用远小于文件大小。想看文件本身多大用 `-A`（apparent size）或 `ls -l`。

---

## 四、实用组合

```bash
# 找当前目录下最大的 10 个目录/文件
du -ah -d 1 | sort -rh | head -10

# 找 /var 下前 20 大项（含文件）
du -ah -d 2 /var | sort -rh | head -20

# 排除 .git 目录的统计（开发项目常用）
du -sh -I '.git'

# 只看特定扩展名的文件大小
find . -name '*.log' -exec du -ch {} + | tail -1
```

---

## 五、踩坑清单

- **坑一：`du -sh *` 不包含隐藏文件（`.` 开头）** → 用 `du -sh .[!.]* *` 或 `du -sh`（汇总当前目录）。
- **坑二：不加 `-d` 输出爆炸** → 养成加 `-d N` 的习惯。`-d 2` 是最实用的日常用法。
- **坑三：`du` 和 `ls -l` 显示的大小可能不同** → du 是磁盘占用（块对齐），ls 是文件字节数。稀疏文件和大量小文件时差异明显。
- **坑四：跨文件系统时 `du -x` 限制在当前文件系统** → 不加 `-x` 时 `/` 下的 du 可能递归到 mount 的 NFS/CIFS 远程目录，卡住很久。
- **坑五：`sort -h` vs `sort -n`** → `-h` 能正确排序 1K < 1M < 1G。`sort -n` 把 1G 当成 1 处理。**排序 du 输出用 `sort -rh`。**

## 六、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 查看目录/文件大小 | du | 标准工具，无处不在 |
| 交互式浏览磁盘占用 | `ncdu` | 和 du 数据一样，但可以上下导航、按目录深入 |
| 查看整个文件系统的剩余空间 | `df` | du 看"用了多少"，df 看"还剩多少" |
| 找大文件（不限于目录汇总） | `find -size` | `find / -size +100M` 找单个大文件更快 |

---

> **核心观点：** 学 du 只需要记住三个选项组合：**`du -sh`**（当前目录总大小）、**`du -h -d 2 | sort -rh | head`**（两级深度 + 排序）、**`du -ah -d 1 | sort -rh | head`**（含文件 + 排序）。这三个组合覆盖 90% 的磁盘排查场景。
