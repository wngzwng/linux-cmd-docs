
# uniq：去重之前先 sort——统计频率、找重复行、过滤唯一行

如果你在排查日志时想知道"哪些 IP 访问最多"，你大概会写：

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```

这条命令里，`uniq -c` 是核心——它把连续的相同行合并并计数。但如果你省略了前面的 `sort`，结果会让你怀疑人生：**uniq 只合并连续相同的行，跳过一个就漏一个。**

这个"连续"的前提条件是 uniq 身上最大的坑，也是本文要讲的第一件事。

---

## 场景引入：去重失败的那个下午

你有一个文件 `ips.txt`：

```
192.168.1.1
10.0.0.1
192.168.1.1
10.0.0.1
192.168.1.1
```

你想知道每个 IP 出现了几次。新手做法：

```bash
uniq -c ips.txt
# 输出：
# 1 192.168.1.1
# 1 10.0.0.1
# 1 192.168.1.1
# 1 10.0.0.1
# 1 192.168.1.1
```

什么？全是一个？不是说好了去重吗？

原因：**uniq 只合并相邻的重复行。** 上面的文件里相同 IP 之间被其他 IP 隔开了，所以 uniq 认为它们不连续——不合并。

正确做法：

```bash
sort ips.txt | uniq -c
# 输出：
# 2 10.0.0.1
# 3 192.168.1.1
```

先 sort 让相同的行排在一起，再 uniq 才能正确去重。

---

## 核心概念：uniq 做的是"合并相邻重复"，不是"全量去重"

uniq 的核心逻辑：**比较相邻两行，如果相同就合并（或删除、或计数）。** 它不维护"见过哪些行"的全局记忆——它只看上一行。

这也是 uniq 比 `sort -u` 更有用的原因：`sort -u` 直接去重，不告诉你"哪些重复了、重复了几次"。uniq 可以告诉你"每样东西出现了几次"——前提是它先排好队。

## 先排雷：永远在 uniq 之前先 sort

```bash
# ❌ 错误：直接 uniq
cat file.txt | uniq -c

# ✅ 正确：先 sort 再 uniq
cat file.txt | sort | uniq -c

# ✅ 或者直接用 sort -u（如果你只需要去重，不需要计数）
sort -u file.txt
```

> 💡 **`sort -u` = `sort | uniq`**，但前者一条命令完成。需要计数或看重复项时用 `sort | uniq -c`，只需要去重用 `sort -u`。

## 核心能力逐层拆解

### 1. 基础去重

```bash
sort file.txt | uniq              # 去重（相邻重复的只保留一个）
sort -u file.txt                  # 等价，但一条命令
```

### 2. 统计出现次数 `-c`（最常用的场景）

```bash
sort file.txt | uniq -c           # 每行前面加出现次数
# 1 apple
# 3 banana
# 2 cherry

# 按频率排序——经典组合
sort file.txt | uniq -c | sort -rn
```

### 3. 只看有重复的行 `-d`

```bash
sort file.txt | uniq -d           # 只显示出现超过一次的行
# banana
# cherry
```

### 4. 只看唯一的行 `-u`

```bash
sort file.txt | uniq -u           # 只显示恰好出现一次的行
# apple
```

> ⚠️ 注意：`uniq -u` 和 `uniq` 不一样。`uniq` 是去重（重复的保留一条），`uniq -u` 是**只输出那些完全不重复的行**。

### 5. 跳过前 N 个字段 `-f`

```bash
# 文件每行是 "日期 事件描述"
# 2025-07-13 ERROR disk full
# 2025-07-13 ERROR disk full

# 忽略日期字段，只看事件是否重复
sort file.txt | uniq -f1 -c
# -f1：跳过第 1 个字段（按空白分隔），从第 2 个字段开始比较
```

## 场景驱动

### 1. 日志分析：Top 10 访问 IP

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
# 拆解：
# awk：提取 IP（第一列）
# sort：让相同 IP 排在一起
# uniq -c：统计每个 IP 出现次数
# sort -rn：按次数倒序排列
# head -10：只看前 10
```

### 2. 找日志中重复的错误行

```bash
grep "ERROR" app.log | sort | uniq -d
# 只看在日志中至少出现了两次的 ERROR 行
# 用于发现"同一个错误反复报"的模式
```

### 3. 检查配置文件中是否有重复行

```bash
grep -v '^\s*#' nginx.conf | sort | uniq -d
# 去掉注释后，检查有没有重复配置
```

### 4. 统计目录下每种文件扩展名的数量

```bash
ls | awk -F. '{print $NF}' | sort | uniq -c | sort -rn
# awk -F. '{print $NF}'：取文件名最后一段（扩展名）
```

## 新手踩坑总结

- **坑一：最大的坑——忘了先 sort。** uniq 只合并相邻的重复行。记住口诀：**"去重之前先排队"**。
- **坑二：`uniq -u` 不是 `uniq`。** `-u` 是只输出唯一的行（出现恰好一次），不是去重。
- **坑三：`uniq -c` 的输出带前导空格。** 数字前会有空格对齐，如果后续用 awk 提取，注意 `$1` 是计数值。
- **坑四：uniq 不能跨字段匹配。** 它比较的是整行。如果要按某列去重，先用 awk 提取该列再 pipe。

---

## 什么时候换工具

| 需求 | uniq 行不行 | 替代方案 |
|------|----------|---------|
| 简单去重 | 行（先 sort） | `sort -u` 更简洁 |
| 统计频率 | 行（`-c`） | `awk '{cnt[$1]++} END {for (k in cnt) print cnt[k], k}'` |
| 不排序去重 | 不行 | `awk '!seen[$0]++'` |
| 按某列去重 | 不行 | `sort -k2 | uniq -f1` 或 awk |

---

## 最后

uniq 是最容易让新手产生"我明明去重了怎么还有重复"困惑的命令。记住了：它不是"去重"，是"合并相邻重复"——这六个字的区别，就是你排查五分钟后恍然大悟的原因。

下次你想知道"什么出现了几次"，别犹豫：`sort | uniq -c | sort -rn`。这是 Linux 管道哲学里最经典的三段式之一。
