# 为什么 ss 很强，但大多数人还在用 `netstat`？

> 很多人排查网络问题时，第一反应还是敲 `netstat -an | grep 8080`。其实 netstat 早已被 ss 取代——ss 更快、更精确、语法更简洁。它的强大不在于"看端口"，而在于把 socket 当成一个可查询的数据集。

## 一、你会遇到的场景

某天你启动服务时报错：`bind: address already in use`——端口被占了。

新手的做法：`netstat -anp | grep 8080`，慢，而且输出格式复杂。非 root 用户看不到进程名，还得加 sudo 再来一遍。

而真正理解 ss 的人，一行解决：

```bash
ss -tlnp 'sport = :8080'
```

瞬间告诉你谁在监听 8080 端口、进程名是什么、PID 是多少。

**这就是 ss 的核心价值：查看当前机器的 socket 统计信息——谁在监听哪个端口、连接状态是什么、背后是哪个进程。它是 `socket statistics` 的缩写。**

> ⚠️ ss 是 Linux 特有的命令（属于 iproute2 工具集），macOS/BSD 上不存在。macOS 上等价工具是 `lsof -i`。本文以 Linux 环境为准。

## 二、它是怎么工作的——IO 模型

ss 的本质是 `内核 socket 表 → 按条件筛选 → 格式化输出`：

```
内核 socket 表（/proc/net/* 或 netlink）
    │
    ↓ 按协议筛选：只看 TCP？还是 UDP？UNIX socket？
    │
    ↓ 按状态筛选：只看 LISTEN 状态？还是 ESTABLISHED？
    │
    ↓ 按过滤表达式筛选：只看某个端口？某个地址？
    │
    ↓ 格式化输出：数字端口号（-n）+ 进程信息（-p）
    │
stdout：socket 列表
```

> 💡 ss 默认输出很多 socket——不仅是 TCP/UDP，还包括 UNIX domain socket。但 **ss 不是一个"显示所有 socket"的工具，而是一个 socket 查询引擎**——你的任务不是背诵参数，而是构造查询条件，精确描述你要看的 socket。

## 三、语法骨架——先把句型刻进脑子里

```
ss  [协议/状态/格式选项]  [过滤表达式]
     ───────┬───────     ────┬───
           筛选轴              过滤轴
```

属于**骨架模式 D**：`查询 + 展示`。同一模式的命令还有 ps、top、df、du——它们都是"从系统取数据 → 按维度展示"。

⚠️ **在讲具体能力之前，先排两个新手几乎必踩的雷：**

### 雷一：不加 `-n` 反而更慢

```bash
# ❌ 不推荐：ss 会尝试把 IP 反解成主机名、端口号反解成服务名——每个都做 DNS 查询
ss -tlp

# ✅ 加 -n：直接显示数字，瞬间出结果
ss -tlnp
```

> ⚠️ **不加 `-n` 反而更慢，这是很多人的直觉反过来的。** 认为"数字不直观"所以不加 `-n`，结果每个 IP 和端口都要反解——在生产环境几百个连接的情况下可能卡好几秒。

### 雷二：不加协议选项不会显示"全部"——默认只显示部分类型

```bash
# ❌ 以为不带 -t -u 会显示所有 socket——实际上默认只显示 ESTABLISHED 状态的 TCP
ss    # 不是你期望的"全部"

# ✅ 明确指定要看什么
ss -tuna    # -t TCP, -u UDP, -n 数字, -a 全部状态（含 LISTEN）
```

## 四、核心能力逐轴拆解

ss 的能力沿 4 个轴展开。不要背选项——每个轴回答一个具体问题，各轴正交，自由组合。

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 协议轴 | TCP 还是 UDP？ | `-t`(TCP)、`-u`(UDP)、`-x`(UNIX)、`-4`(IPv4)、`-6`(IPv6) |
| 状态轴 | 监听中还是已建立？ | `-l`(监听)、`-a`(全部)、不指定=默认仅 ESTABLISHED |
| 显示轴 | 数字还是名称？进程是谁？ | `-n`(数字)、`-p`(进程)、`-r`(反解)、`-e`(扩展信息) |
| 过滤轴 | 只看特定端口/地址？ | `sport = :8080`、`dport = :443`、`src 192.168.1.0/24` |

---

### 轴 1：协议轴——"看哪种 socket？"

> 场景：你只关心 TCP 连接，不想被 UNIX socket 输出淹没。

```bash
# 只看 TCP
ss -t

# TCP + UDP 一起看
ss -tu

# 只看 UNIX domain socket（本地进程间通信）
ss -x

# IPv4 only
ss -4

# IPv6 only  
ss -6
```

---

### 轴 2：状态轴——"什么状态的连接？"

> 场景：你想看哪些端口正在监听（服务是否启动了），或者看哪些连接是 ESTABLISHED 的（谁在连我）。

```bash
# 只看正在监听的端口
ss -tln    # TCP + 监听 + 数字端口

# 全部状态（LISTEN + ESTABLISHED + TIME_WAIT + ...）
ss -tan

# 只看 ESTABLISHED（当前活跃连接）
ss -tn state established

# 看 TIME_WAIT（连接关闭后的残留——排查端口耗尽）
ss -tan state time-wait
```

---

### 轴 3：显示轴——"输出什么格式？"

> 场景：你不仅要端口号，还要知道是哪个进程在监听。

```bash
# -n: 数字端口号（不解析成服务名）
ss -tln

# -p: 显示进程名和 PID（需 root 权限才能看其他用户的进程）
sudo ss -tlnp

# -e: 扩展信息（包括 uid、inode、超时等）
ss -tne

# -m: 内存使用情况（socket 缓冲区大小）
ss -tm
```

> ⚠️ **非 root 用户看不到其他用户的进程信息。** `-p` 在非 root 下只显示自己进程的详细信息。如果你发现 `ss -tlnp` 的输出里进程栏是空的——试试加 `sudo`。

---

### 轴 4：过滤轴——"只要某个端口或地址？"

> 场景：你只关心 8080 端口，不想在几百行输出里肉眼搜索。

```bash
# 只看源端口 8080（谁在监听？）
ss -tlnp 'sport = :8080'

# 只看目标端口 443（谁在连外网？）
ss -tnp 'dport = :443'

# 只看特定源地址
ss -tn 'src 192.168.1.100'

# 复杂过滤：来自 10.0.0.0/8 网段到 443 的连接
ss -tn 'src 10.0.0.0/8 and dport = :443'

# 状态+端口组合
ss -tn 'state established and dport = :80'
```

> 💡 过滤表达式是 ss 的**杀手级特性**——它让你从"看所有 socket 然后肉眼 grep"变成了"精确描述你要找的连接"。这和 SQL 的 `WHERE` 子句本质上是一样的。

## 五、真实排障全流程复盘

回到开头的场景：端口被占用。

**第一步：确认——8080 被谁占了？**
```bash
ss -tlnp 'sport = :8080'
```
输出直接告诉你 PID 和进程名。如果没输出，说明 8080 没有被 TCP 监听——可能是 UDP 或其他协议。

**第二步：扩大范围——是不是 UDP 端口？**
```bash
ss -ulnp 'sport = :8080'
```

**第三步：如果都找不到——所有状态的 socket 都看一看**
```bash
ss -tuanp | grep 8080
```

**第四步：处理——kill 掉占端口的进程，或者改配置**
```bash
kill -9 <PID>
# 或者改你服务的监听端口
```

## 六、踩坑清单

- **坑一：不加 `-n` 反而更慢** → DNS 和服务名反解耗时远超预期，排查问题永远带 `-n`
- **坑二：非 root 看不到进程信息** → `-p` 需要 sudo 才能看全，没显示不代表没有
- **坑三：默认输出不含 LISTEN 状态** → 不带 `-l` 或 `-a` 时只显示 ESTABLISHED，排查"端口被占用"时一定要加 `-l`
- **坑四：`127.0.0.1:8080` 只有本机能访问** → 看到 `127.0.0.1` 监听时，说明只绑定了回环地址，外部无法访问。如果要对外暴露，服务需要绑定 `0.0.0.0` 或具体网卡 IP
- **坑五：TIME_WAIT 多不是问题** → 大量 TIME_WAIT 通常是正常的（短连接多），不要急着调内核参数。但如果 TIME_WAIT + 端口不够用，才是真问题

## 七、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 查端口占用、连接状态 | ss | 这正是 ss 的设计领域——快、过滤表达式强大 |
| macOS/BSD 上查端口 | `lsof -i` | ss 不存在于非 Linux 系统 |
| 查进程打开了哪些文件/socket | lsof | lsof 以进程为中心，ss 以 socket 为中心 |
| 实时流量监控 | `iftop` / `nload` | ss 是快照，不是实时监控 |
| 抓包分析 | `tcpdump` | ss 是统计工具，不抓包 |

---

> **核心观点：** 学 ss 不是为了记住 `ss -tlnp` 这个固定组合，而是理解它的 **IO 模型**（内核 socket 表 → 筛选 → 格式化）和 **4 个能力轴**（协议、状态、显示、过滤）。一旦这两个立住了，任何"查端口"的需求你都能从轴里选出组合，命令自然生成。
>
> 下次你敲 `netstat` 的时候，想想——是不是该换 ss 了？
