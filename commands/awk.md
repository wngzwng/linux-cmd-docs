# awk：按列处理文本——从 `{print $1}` 到条件统计和累加

> 很多人用了好几年 Linux，awk 永远只会一种用法——`awk '{print $1}'` 提取第一列，再复杂一点就换 Python 了。其实 awk 是一門完整的编程语言，`{print $1}` 只是它能力的冰山一角。

## 一、你会遇到的场景

某天你拿到一份 500MB 的访问日志，老板让你统计「每个 IP 的请求次数，按从高到低排列」。

新手的反应往往是：打开 Python，写十几行代码，读文件、split、建字典、排序、打印——写完三分钟过去了。或者更糟的：把文件下载到本地用 Excel 打开，直接卡死。

而真正理解 awk 的人，一行搞定：

```bash
awk '{cnt[$1]++} END {for (ip in cnt) print cnt[ip], ip}' access.log | sort -rn | head -10
```

几秒钟之后，Top 10 IP 一目了然。

**这就是 awk 的核心价值：逐行扫描文本，按模式匹配后执行动作——它是一门专为文本流处理设计的编程语言。** 它不是"列提取工具"，它是一个嵌入在命令行里的数据处理引擎。

## 二、它是怎么工作的——IO 模型

awk 的本质不是 `command + options`，而是 `逐行读入 → 模式匹配 → 动作执行 → 输出`：

```
输入文件（或 stdin）
    │
    ↓ BEGIN 块：读第一行之前执行一次（初始化变量、打印表头）
    │
    ↓ 对每一行：
    │   ├─ 按 FS（字段分隔符）拆成 $1, $2, ... $NF
    │   ├─ 用模式（pattern）匹配这一行
    │   └─ 匹配成功 → 执行 { action }
    │      匹配失败 → 跳过，读下一行
    │
    ↓ END 块：读完最后一行后执行一次（汇总、打印结果）
    │
输出：print/printf 的内容
```

> 💡 理解了 IO 模型，很多概念就自然出现了：`BEGIN` 和 `END` 控制"什么时候执行"，`pattern` 控制"对哪些行执行"，`{ action }` 控制"执行什么"。`$1`、`NF`、`NR` 这些变量是 awk 帮你自动维护的行状态——你不需要手动 split、不需要手动计数。

## 三、语法骨架——先把句型刻进脑子里

```
awk  [选项]  'pattern { action }'  [文件...]
     ─┬─     ───────┬───────       ──┬──
     选件槽          程序槽           输入槽
```

属于**骨架模式 E**：`输入 → 转换 → 输出`。同一模式的命令还有 sed、cut、sort、uniq——它们都是对文本流做变换。但 awk 的独特之处在于：它的"转换规则"不是几个参数，而是一门语言。

⚠️ **在讲具体能力之前，先排两个新手几乎必踩的雷：**

### 雷一：`$1` 不是 shell 变量！

```bash
# ❌ 错误：shell 会先把 $1 展开成 shell 的第一个参数（通常是空），然后 awk 收到的程序变成 '{print }'
awk '{print $1}' data.txt
# 在交互式 shell 里这行其实能正常跑——因为交互式 shell 的 $1 通常是空，awk 收到的是原样。
# 但在脚本里如果外层用了 set，$1 就有值了——灾难！

# ✅ 正确：用单引号保护 awk 程序，不让 shell 碰 $
awk '{print $1}' data.txt
```

规则：**awk 程序永远用单引号 `'...'` 包裹。** 单引号里的一切 shell 都不会展开。`$1` 在单引号里被完整地传给 awk，由 awk 来解释成"第一个字段"。如果放到双引号里，shell 会把 `$1` 当成自己的变量先展开，awk 收到的可能已经面目全非。

### 雷二：`print` 和 `print $0` 不是一回事？

```bash
# 这两行效果完全一样，都打印整行
awk '{print}' data.txt
awk '{print $0}' data.txt
```

在 awk 里，**`print` 不带参数等价于 `print $0`**——打印当前行的完整内容。但你可能会疑惑：什么时候用 `print` 什么时候用 `print $0`？答：用哪个都行，但 `print` 更简洁；当你要在 `$0` 前后拼接别的内容时，必须显式写 `print "prefix", $0`。**一个新手常犯的误会是以为 `print` 什么都不打印——它打印整行。**

## 四、核心能力逐轴拆解

awk 的能力沿 5 个轴展开。不要背语法——每个轴回答一个具体问题，各轴正交，自由组合。

| 能力轴 | 问题 | 核心机制 |
|--------|------|---------|
| 字段轴 | 一行里的第几列？ | `$1`, `$2`, `$NF`, `FS`, `-F` |
| 模式轴 | 处理哪些行？ | `/regex/`, `NR==n`, `$n ~ /pat/`, 范围模式 |
| 状态轴 | 在处理第几行/哪个文件？ | `NR`, `FNR`, `NF`, `FILENAME` |
| 计算轴 | 怎么跨行累加/统计？ | 变量、数组、`BEGIN`/`END` |
| 格式化轴 | 输出长什么样？ | `print`, `printf`, `OFS`, `ORS` |

---

### 轴 1：字段轴——"这一行里我要哪一列？"

> 场景：你有一个 CSV 文件，只想看第 3 列和第 1 列。

```bash
# 默认以空白字符（空格/Tab）分隔
awk '{print $3, $1}' data.txt

# 以逗号分隔——处理 CSV
awk -F, '{print $3, $1}' data.csv

# 以冒号分隔——处理 /etc/passwd
awk -F: '{print $1, $7}' /etc/passwd
```

`-F` 指定输入字段分隔符（FS），它接收的其实是一个**正则表达式**：

```bash
# 分隔符是逗号或分号——二者之一都算
awk -F'[,;]' '{print $2}' data.txt

# 分隔符是一个或多个空格（默认行为）
awk -F'[ ]+' '{print $1}' data.txt
```

> 💡 `$0` 是整行，`$1`～`$NF` 是每个字段，`$NF` 是最后一个字段（`NF` 是字段数量）。`$(NF-1)` 是倒数第二个——这在很多场景下非常有用：日志格式不固定时，倒数第二列往往是固定含义。

> ⚠️ **`$` 后面可以是变量或表达式，不只是数字。** `$NF` 取最后一个字段，`$(NF-1)` 取倒数第二个字段。这是 awk 独有的灵活性——大多数人在 awk 里只用 `$1`、`$2` 这种数字索引，完全没意识到可以动态计算列号。

---

### 轴 2：模式轴——"我要处理哪些行？"

> 场景：日志里混杂了 INFO、WARN、ERROR，你只想看 ERROR 行；或者你只想处理第 10～20 行。

```bash
# 正则模式：包含 ERROR 的行
awk '/ERROR/' app.log

# 字段匹配：第 3 列等于 "500" 的行
awk '$3 == "500"' access.log

# 行号范围：第 10 到第 20 行
awk 'NR>=10 && NR<=20' data.txt

# 正则匹配特定字段：第 1 列以 "192.168" 开头的行
awk '$1 ~ /^192\.168/' access.log

# 范围模式：从 "START" 到 "END" 之间的所有行
awk '/START/,/END/' data.txt
```

核心机制：**模式是过滤器，不是选择器。** 模式为真的行，执行 `{ action }`；模式为假的行，跳过。如果省略 `{ action }`，默认动作就是 `print`——所以 `awk '/ERROR/'` 等价于 `grep ERROR`。

> ⚠️ **`print` 不是 awk 的唯一输出方式。** 很多人以为 awk 只能 `print`，其实 `printf` 可以做精确格式化，和 C 语言的 `printf` 语法一致。字段之间用什么分隔、行尾加不加换行，全由 `OFS` 和 `ORS` 变量控制——但这些变量只在 `print` 中生效，`printf` 需要手动处理分隔符。

---

### 轴 3：状态轴——"我在处理第几行？哪个文件？"

> 场景：你要给输出加上行号，或者区分数值行和标题行。

```bash
# 加行号
awk '{print NR, $0}' data.txt

# 跳过第一行（标题行）
awk 'NR > 1 {print $1}' data.csv

# 看每一行有多少个字段（快速检查CSV列数是否一致）
awk '{print NR, NF, $0}' data.csv

# 知道当前在处理哪个文件（多文件场景）
awk '{print FILENAME, NR, FNR, $0}' file1.txt file2.txt
```

关键变量解释：

| 变量 | 含义 | 典型用途 |
|------|------|---------|
| `NR` | 已处理的总行数（跨文件累加） | 全局行号、`END` 中算总数 |
| `FNR` | 当前文件内的行号（每个文件重置） | 多文件时区分"第几个文件的第几行" |
| `NF` | 当前行的字段数 | 检查列数、取最后一列 `$NF` |
| `FILENAME` | 当前文件名 | 多文件处理时标识来源 |

---

### 轴 4：计算轴——"怎么跨行累加、分组统计？"

> 场景：这是 awk 真正的杀手级能力——逐行扫描、跨行累加、END 汇总。

```bash
# 求和：第二列的累加
awk '{sum += $2} END {print "total:", sum}' data.txt

# 平均值
awk '{sum += $2} END {print "avg:", sum/NR}' data.txt

# 分组统计（关联数组！）：每个 IP 出现多少次
awk '{cnt[$1]++} END {for (ip in cnt) print cnt[ip], ip}' access.log

# 分组求和：每个用户的消费总额
awk '{total[$1] += $3} END {for (user in total) print user, total[user]}' orders.txt
```

核心机制：awk 的变量在行之间保持状态。`sum` 在第一行赋值为 `$2`，第二行变成 `sum + $2`，一直累加到文件末尾。`END` 块在所有行处理完后执行一次——这就是 awk 做统计的根本原理。

而**关联数组**是 awk 真正的王牌：下标可以是任意字符串，不需要预先声明大小，天然适合做分组聚合。

```bash
# 更复杂的例子：统计每个状态码的出现次数，按数值排序
awk '{cnt[$3]++} END {for (code in cnt) print cnt[code], code}' access.log | sort -rn
```

> ⚠️ **awk 的数组遍历顺序是不确定的。** `for (key in array)` 的遍历顺序取决于内部实现，不是按插入顺序、也不是按键排序。**如果需要有序输出，必须把结果 pipe 给 `sort`，不要在 awk 内依赖遍历顺序。**

---

### 轴 5：格式化轴——"输出长什么样？"

> 场景：你想输出表格、固定列宽、或者 CSV 格式。

```bash
# 用 printf 精确控制格式：左对齐 15 字符宽的用户名 + 右对齐 10 字符宽的金额
awk '{printf "%-15s %10.2f\n", $1, $2}' data.txt

# 修改输出字段分隔符——输出 CSV
awk -v OFS=, '{print $1, $2, $3}' data.tsv

# 修改输出行分隔符——用分号结束每行
awk -v ORS=';\n' '{print $0}' data.txt
```

`print` 用 `OFS` 连接多个字段，用 `ORS` 结尾。`printf` 给你完全的格式控制，和 C 的 `printf` 相同。选择原则：快速输出用 `print`，需要对齐/小数位数/十六进制用 `printf`。

---

## 五、Pipeline 组合——把 awk 串进流水线

awk 真正的战场在管道中间——它接受 stdin、输出到 stdout，天然适合做流水线的一个环节：

```
cat access.log
    │  输出：原始日志行
    ↓
awk '{print $1}'       （提取 IP 列）
    │  输出：每行一个 IP
    ↓
sort                   （排序——uniq 需要相邻行）
    │  输出：排序后的 IP 列表
    ↓
uniq -c                （统计相邻重复行）
    │  输出：次数 + IP
    ↓
sort -rn               （按次数降序）
    │  输出：从高到低排列
    ↓
head -10               （Top 10）
```

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```

> 💡 这里能串起来的关键是：awk 输出的是一个字段（纯文本 IP），恰好是 `sort` 接受的文本行，而 `sort` 的输出恰好是 `uniq -c` 期望的排好序的列表。每一步的 IO 格式都是匹配的。

**但更高效的写法是把分组逻辑放在 awk 内：**

```bash
awk '{cnt[$1]++} END {for (ip in cnt) print cnt[ip], ip}' access.log | sort -rn | head -10
```

管道里只剩两步：awk 做分组+计数，sort 做排序。不需要 sort → uniq → sort 的三步链。**这背后是一个重要的决策原则：当分组逻辑可以在 awk 的关联数组里完成时，不要让数据多次穿过管道——管道越短越快。**

## 六、踩坑清单

- **坑一：`$1` 被 shell 吃掉** → awk 程序永远用单引号 `'...'` 包裹，别用双引号
- **坑二：`print` 和 `print $0` 混用导致多出空格** → `print $1, $2` 会用 `OFS`（默认空格）连接；`print $1 $2` 是字符串拼接，中间没有分隔符。差一个逗号，结果完全不同
- **坑三：`NR` 算上了标题行** → 有标题的 CSV 记得 `NR > 1` 跳过第一行，或者 `FNR == 1 {next}` 跳过每个文件的第一行
- **坑四：关联数组遍历顺序不可靠** → 需要排序时，在 awk 外面接 `sort`，不要在内部依赖遍历顺序
- **坑五：数字和字符串的边界模糊** → awk 会根据上下文自动转换。字符串 "123" 用在算术里就是数字 123；但 "abc" + 1 = 1（非数字字符串视为 0）。**用 `$2 + 0` 强制转数字，用 `$2 ""` 强制转字符串。**
- **坑六：`-F` 后面跟正则时忘了转义** → `-F.` 会被当成正则的 `.`（匹配任意字符），用 `-F'\\.'` 或 `-F'[.]'` 精确匹配点号

## 七、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 按列提取、简单统计、分组聚合 | awk | 这正是 awk 的设计领域——逐行处理+关联数组 |
| 复杂的多行替换、正则替换 | sed | sed 的替换语法更简洁，awk 的 sub/gsub 适合在字段内替换 |
| 只需要筛选包含某模式的行 | grep | grep 更快更简洁，不需要 awk 的字段拆分开销 |
| 处理 JSON/XML/结构化数据 | jq / xmllint | awk 不解析嵌套结构，层次数据用专用工具 |
| 复杂数据分析、需要 DataFrame | Python pandas / R | awk 的数组是一维关联数组，不适合二维表格操作 |
| 超大文件的聚合（10GB+） | 考虑用数据库或专门工具 | awk 是内存中处理，关联数组可能占满内存 |

## 八、换个命令你会了吗？

awk 属于**骨架模式 E**：`输入 → 转换 → 输出`。同一模式的命令还有：

- **sed**：流编辑器——`sed 's/old/new/'` 也是逐行处理，语法是 `地址 { 命令 }`，和 awk 的 `模式 { 动作 }` 如出一辙
- **cut**：简化版的列提取——`cut -d, -f1` ≈ `awk -F, '{print $1}'`，但 cut 只能提取不能计算
- **sort / uniq**：排序和去重——它们接受文本流、输出文本流，通常是 awk 的下游搭档

学完 awk，你其实已经掌握了"输入→转换→输出"这一类命令的核心思维。**下次遇到 sed，先问自己：它的输入是什么？模式/地址怎么匹配？动作是什么？** 三个问题答上来，sed 的语法自然通了。

> **核心观点：** 学 awk 不是为了记住 `{print $1}` 这个固定写法，而是理解它的 **IO 模型**（逐行读入 → 模式匹配 → 动作执行 → END 汇总）和 **5 个能力轴**（字段、模式、状态、计算、格式化）。一旦这两个立住了，任何"从文本里提取/统计/汇总"的需求你都能从轴里选出组合，填入骨架，命令自然生成。
