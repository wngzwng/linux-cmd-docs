# 为什么 htop 比 top 好，但你还在用 top？

> 很多人知道 `htop` 比 `top` 好看，安装了却从来不打开——肌肉记忆还是敲 `top`。其实 htop 不只是"彩色的 top"，它把进程管理变成了一个可交互的仪表盘。

## 一、你会遇到的场景

某天 CPU 飙到 100%，你想看看是哪个进程、它在跑哪个线程、它在读什么文件。

`top` 的做法：看 PID → 退出 top → `ps -Lf PID` 看线程 → `lsof -p PID` 看打开的文件。三个命令来回切换。

`htop` 的做法：F2 进设置 → 加 THREAD 列 → 直接看到线程信息；光标移到进程上 → 按 `l`（strace）或 `s`（显示打开文件）——一切都在同一个界面里完成。

**这就是 htop 的核心价值：交互式进程查看器——彩色、可滚动、支持鼠标、内置进程操作快捷键。**

## 二、概念模型——htop 的界面是什么

htop 的界面三层：

```
顶部仪表盘（CPU 条、内存条、Swap 条——可自定义）
    │
进程列表（可上下滚动、可鼠标点击选择、可按任意列排序）
    │  每行一个进程：PID USER PRI NI VIRT RES SHR S CPU% MEM% TIME+ Command
    │  线程默认合并显示，可展开
    │
底部功能键（F1-F10，可自定义）
    F1=Help F2=Setup F3=Search F4=Filter F5=Tree F6=SortBy
    F7=Nice- F8=Nice+ F9=Kill F10=Quit
```

> 💡 htop 和 top 本质的区别是：**top 是"看"，htop 是"操作"。** 在 htop 里你可以直接在进程列表里导航、搜索、排序、发信号、strace、看文件——不需要退出之后再用其他命令。

## 三、核心操作维度

不列所有快捷键——按场景分组。

### 场景 1：定位——"找到那个吃 CPU 的进程"

```bash
# 启动 htop
htop

# 进入后：
# F3 或 /   → 搜索进程名
# F4        → 过滤器（只显示匹配的进程——比搜索更好用）
# F6        → 选择排序列（默认按 CPU%，可以切到 MEM%、TIME 等）
# 鼠标点击列头 → 直接排序
```

> 💡 `F4`（过滤器）是 htop 最被低估的功能——输入 `java` 后，进程列表只剩名字里含 java 的进程，你可以在这个过滤视图里做任何操作。

### 场景 2：操作——"杀掉或调整它"

```bash
# F9        → 发送信号（默认 15 SIGTERM，可选 9 SIGKILL）
# F7 / F8   → 调整 nice 值（降低/提高优先级）
# 空格键    → 标记进程（标记多个后批量操作）
# a         → 设置 CPU 亲和性（把进程绑定到特定 CPU 核心）
```

### 场景 3：深入——"这个进程在干什么？"

```bash
# l         → lsof：显示进程打开的文件
# s         → strace：追踪系统调用（需要 strace 安装）
# L         → ltrace：追踪库函数调用
# t         → 切换线程视图（展开/折叠线程）
# H         → 切换用户线程/内核线程显示
```

> 💡 htop 的 `l`（lsof）是最实用的快捷功能——选中一个进程按 `l`，立刻看到它打开了哪些文件。不需要退出 htop、敲 `lsof -p PID`、再回来。

### 场景 4：定制——"让仪表盘显示你关心的"

```bash
# F2        → 进入设置
#   Meters  → 添加/移除顶部仪表盘项（CPU、内存、网络、磁盘 IO、电池...）
#   Display options → 主题、更新间隔、显示用户名/完整命令行
#   Colors  → 配色方案
```

### 场景 5：快捷翻页

| 按键 | 作用 |
|------|------|
| `u` | 只看某个用户的进程 |
| `p` | 显示完整程序路径 |
| `k` | 隐藏内核线程 |
| `i` | 设置 IO 优先级 |
| `Ctrl+L` | 刷新显示 |
| `q` / `F10` | 退出 |

## 四、踩坑清单

- **坑一：htop 不是预装的** → `apt install htop`、`brew install htop`。生产环境可能没有安装权限，那就只能 top 了。
- **坑二：`l`（lsof）和 `s`（strace）需要对应工具已安装** → 如果没有 lsof/strace，这些快捷键无效。但至少 `l` 在大多数机器上可以工作。
- **坑三：htop 比 top 消耗略多的 CPU** → 在极度资源紧张的服务器上（0.1% CPU 都要抠的场景），top 更轻量。
- **坑四：`F4` 过滤器和 `F3` 搜索的区别** → F3 是跳转（高亮匹配项），F4 是只显示匹配的进程（过滤后列表更干净）。排查特定服务时用 F4。

## 五、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 交互式进程监控和操作 | htop | 彩色、鼠标、快捷操作——体验最好的进程仪表盘 |
| 资源极受限的环境 | top | htop 不在时用 top，top 的关键快捷键（1/M/P/k）也是通用的 |
| 脚本中获取进程数据 | `ps` | htop/top 都是交互式工具，脚本用 ps |
| 查看历史资源使用 | `sar` / `atop` | htop 没有历史记录，只看当前 |
| 更详细的 IO/网络进程分析 | `iotop` / `nethogs` | htop 主要看 CPU/内存，IO 和网络信息有限 |

---

> **核心观点：** htop 不是"彩色的 top"——它是把进程管理从"被动查看"升级为"主动操作"的工具。它的核心价值在三个快捷键：**F4**（过滤）、**F9**（kill）、**`l`**（lsof）。这三个快捷键让进程排查从 3 个命令 → 0 个命令切换。
>
> 今天就把 `alias top='htop'` 写进 `.bashrc` 吧。
