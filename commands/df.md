# df：磁盘还剩多少？一眼看完

> `df` 可能是最直接的系统管理命令——它告诉你磁盘还剩多少空间。但 `-h`（人类可读）和 `-i`（inode 使用率）藏着两个经常被忽略的维度。

## 语法骨架

```
df  [选项]  [文件系统/文件...]
    ──┬──   ─────┬─────
     展示格式    只看哪个
```

## 核心用法

```bash
# 查看所有挂载的文件系统（人类可读）
df -h

# 只看特定文件系统
df -h /

# 显示文件系统类型
df -hT

# 显示 inode 使用情况（⚠️ 这和磁盘空间是不同的资源！）
df -i
```

## 输出解读

```
Filesystem     Size    Used   Avail Capacity  Mounted on
/dev/sda1       50G     45G    2.4G    95%    /
```

| 字段 | 含义 |
|------|------|
| Size | 总大小 |
| Used | 已用（含保留空间） |
| Avail | 可用（普通用户可用） |
| Capacity | 使用率（Used / Size） |
| Mounted on | 挂载点 |

> ⚠️ **Used + Avail ≠ Size。** 文件系统默认保留 5% 给 root（防止普通用户把磁盘写满导致系统不可用）。这 5% 在 Used 里但不计入 Avail。

## inode 耗尽：磁盘有空余但报 "No space left"

```bash
df -i
# 如果 IUse% 列显示 100%——你的 inode 用完了
# 这通常是因为某个目录下有海量小文件（如几十万个 session 文件）
# 解决：找到"文件热区"并清理
find /var -xdev -type f | cut -d/ -f4 | sort | uniq -c | sort -rn | head
```

> 💡 **磁盘空间和 inode 是两种不同的资源。** 磁盘空间是"有多少字节可写"，inode 是"能创建多少个文件"。一个 1KB 的小文件和一个 1GB 的大文件各消耗 1 个 inode。海量小文件优先耗尽 inode。

## 实用组合

```bash
# 只看本地文件系统（排除 tmpfs/snap/docker 等虚拟挂载）
df -h -t ext4 -t xfs -t btrfs

# 只看使用率超过 80% 的文件系统
df -h | awk 'NR==1 || $5+0 > 80'

# 监控模式：每 2 秒刷新
watch -n2 df -h
```

## 踩坑清单

- **坑一：`df -h` 的输出里可能有几十行虚拟挂载（docker/snap/tmpfs）** → 用 `-t` 限定文件系统类型，或用 `-x tmpfs` 排除。
- **坑二：`df` 不实时反映删除大文件后的变化** → 如果进程还持有已删除文件的句柄（lsof | grep deleted），空间不会释放。kill/重启进程后才生效。
- **坑三：NFS 挂载卡住时 `df` 也会卡住** → 网络文件系统无响应时 df 会阻塞。加 `-l`（只显示本地文件系统）避免。

## 什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 看磁盘剩余 | df | 标准工具 |
| 看目录/文件占用 | du | df 看文件系统级别，du 看目录级别 |
| 图形化浏览 | `ncdu` / `baobab` | 交互式探索 |

---

> **核心观点：** `df -h` 是你需要的唯一 df 命令——但别忘了 `df -i`。磁盘没满 ≠ 可以创建新文件，inode 耗尽同样报 "No space left"。
