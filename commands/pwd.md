
# pwd：你以为你知道自己在哪——直到你确实不知道

如果你问任何一个 Linux 用户"pwd 是干什么的"，答案几乎一样："打印当前目录啊，有什么好讲的。" 但如果你问他们"你有没有因为不知道自己到底在哪个目录而出过事"，大多数人都会沉默两秒然后点头。

pwd 的价值不在于它有多复杂——它可能是 Linux 里最简单的命令。它的价值在于：**它是你和文件系统之间的"定位校准器"**。每次你开始一个复杂操作前敲一下 pwd，就少了一个"我以为我在 /tmp 结果我在 /home"的惨案。

这篇文章很短，但会纠正一个很多人用了几十年都没发现的认知偏差。

---

## 场景引入：那个最常见的排障翻车现场

你在远程服务器上排查问题，`cd` 进了一个日志目录，打开文件翻了半天，找到问题根源后准备清理旧日志：

```bash
cd /var/log/nginx
less error.log           # 排障中……
# ……30 分钟后……
rm -rf ./*
```

然后你发现删错了——你刚才 `cd ../../home/user/project` 去看了另一个东西，但忘了。

这不是段子，这是真实发生过的事。老手和新手的区别在于：**老手在按回车之前会先敲一次 `pwd`**。

---

## 核心概念：它不"算"路径，它就是路径

pwd 的逻辑简单到一句话：**它把当前工作目录的绝对路径打印出来。**

`pwd` 全称 **P**rint **W**orking **D**irectory。注意不是"当前所在目录"，而是"当前**工作**目录"——这是操作系统内核维护的一个属性，不是猜出来的。

有两个版本你可能不知道：

```bash
pwd            # Shell 内置命令（大多数情况用的是这个）
/bin/pwd       # 外部程序版本
```

它们 99.9% 的情况下输出一致。唯一有区别的场景是：当你通过软链接进入目录时。

```bash
# 假设 /var/log/nginx 是 /data/log/nginx 的软链接
cd /var/log/nginx

pwd            # 输出 /var/log/nginx（Shell 记住你"怎么去的"）
/bin/pwd       # 输出 /data/log/nginx（实际物理路径）
/bin/pwd -L    # 输出 /var/log/nginx（逻辑路径，默认行为）
/bin/pwd -P    # 输出 /data/log/nginx（物理路径，解析所有软链接）
```

> 💡 绝大多数场景下你不需要关心这个区别。但如果你在排查"文件明明存在但找不到"的问题，可能就是软链接搞的鬼，这时 `pwd -P` 可以帮你看到真相。

## 先排雷：你以为你在家，其实你不在

最常见的误区不是 pwd 怎么用，而是根本不用它。

```bash
# 新手做法：凭记忆
# "我记得刚才 cd 到 /var/log 了，直接 rm 吧"
rm -rf ./*

# 老手做法：每次 destructive 操作前
pwd          # 先确认位置
ls -la       # 再看一眼内容
rm -rf ./*   # 确认无误再删
```

pwd 在这里不是一条命令，而是一个**安全习惯**。就像开车前看后视镜，花半秒钟能避免的事故不需要靠运气。

## 场景驱动：pwd 在实战中的三个位置

### 1. 脚本里获取路径（`$(pwd)` 和 `$PWD`）

```bash
#!/bin/bash
# 你的脚本需要知道自己的运行位置
BACKUP_DIR="$(pwd)/backup"       # 命令替换方式
BACKUP_DIR="$PWD/backup"         # 环境变量方式（更快，不启动子进程）
```

> 💡 `$PWD` 是 Shell 自动维护的环境变量，和 `pwd` 输出一致但不需要 fork 子进程。在脚本里 `$PWD` 比 `$(pwd)` 更高效。

### 2. 复制当前路径到剪贴板

```bash
# macOS
pwd | pbcopy

# Linux（需要 xclip）
pwd | xclip -selection clipboard
```

当你在终端里翻了半天找到了需要的目录，想让别人也 `cd` 过来——不用手输路径，一行复制。

### 3. 在 find 命令中当锚点

```bash
# 在当前目录下搜索，用绝对路径报结果
find "$(pwd)" -name "*.conf"
# 输出：/home/user/project/nginx.conf（绝对路径，一目了然）
```

比 `find . -name "*.conf"` 输出 `./nginx.conf` 有用得多——你可以直接复制路径去编辑。

---

## 新手踩坑总结

- **坑一：最根本的坑——不用 pwd。** 以为自己知道在哪，开始删文件，然后出事。
- **坑二：软链接路径的"幻觉"。** 当你 `cd` 进软链接目录后，`pwd` 显示的是逻辑路径（你怎么进去的），不一定是物理路径。排查"文件找不到"的问题时，试试 `pwd -P`。

---

## 什么时候换工具

pwd 只管"我在哪"这一件事：

| 需求 | pwd 行不行 | 替代方案 |
|------|----------|---------|
| 获取当前目录绝对路径 | 行 | `$PWD` 变量更快 |
| 获取脚本自身的目录（不是运行目录） | 不行 | `dirname "$0"` 或 `$(cd "$(dirname "$0")" && pwd)` |
| 获取上一条命令所在的目录 | 不行 | `cd -` 回到上一个目录 |
| 获取某进程的工作目录 | 不行 | `pwdx <PID>` 或 `ls -l /proc/<PID>/cwd` |

---

## 最后

pwd 是 Linux 里最简单的命令——没有参数争辩，没有版本兼容问题。但它的价值刚好和复杂度成反比：你需要它的时候，通常就是你要犯错的时候。

下次你要执行 `rm`、`mv`、`chmod -R` 之前，试试多敲三个字母。那三个字母可能比你想象的值钱得多。
