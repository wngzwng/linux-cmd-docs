
# cut：按分隔符或字符位置切列——比 awk 更轻量的选择

如果你需要在命令行里提取文件的某一列，你会怎么做？大多数人第一反应是 awk：`awk '{print $2}' file.txt`。这没问题，但 awk 是一把瑞士军刀，而你要做的只是切一刀。

`cut` 就是这一把刀。它比 awk 简单得多，语法清晰，而且——最重要的——**它的按字符切割能力是 awk 没有的。**

---

## 场景引入：两个你默默打开 Excel 的瞬间

### 场景一：只看 /etc/passwd 里的用户名

```bash
# 文件长这样：root:x:0:0:root:/root:/bin/bash
# 你只想要第一列（按 : 分隔的用户名）

# 新手做法：用 awk
awk -F: '{print $1}' /etc/passwd

# 更简单的做法：用 cut
cut -d: -f1 /etc/passwd
```

两条命令结果一样，但 cut 的语法更直觉：`-d` 指定分隔符，`-f` 指定取第几列。

### 场景二：从固定宽度的日志里提取时间戳

有些日志没有分隔符，字段是按固定位置排的：

```
20250713 14:30:15 ERROR disk full
20250713 14:30:16 INFO  retrying
```

你想取每行的前 17 个字符（日期+时间）：

```bash
cut -c1-17 server.log
# 输出：
# 20250713 14:30:15
# 20250713 14:30:16
```

awk 做这件事也很麻烦——你需要 substr。但 `cut -c` 一行搞定。

---

## 核心概念：cut 只做一件事——剪

cut 的核心逻辑：**从每行中剪出指定的部分，丢弃其余。**

它有两种剪法：
- **按分隔符剪（-d -f）**：像切 CSV，指定分隔符和列号
- **按字符位置剪（-c）**：像用剪刀沿标尺剪，指定字符范围

---

## 先排雷：`-d` 只能接单个字符

```bash
# ✅ 单字符分隔符
cut -d: -f1 /etc/passwd         # 冒号分隔
cut -d, -f1,3 data.csv          # 逗号分隔

# ❌ 多字符分隔符——不支持！
cut -d'::' -f1 file.txt         # 报错：分隔符必须是单个字符
```

> 💡 如果你需要用多字符分隔符（如 `::` 或 ` => `），cut 做不了，换 awk：`awk -F'::' '{print $1}' file.txt`。

---

## 核心能力逐层拆解

### 1. 按分隔符提取列 `-d` `-f`

```bash
cut -d: -f1 /etc/passwd         # 取第 1 列
cut -d: -f1,3 /etc/passwd       # 取第 1 列和第 3 列
cut -d: -f1-3 /etc/passwd       # 取第 1 到第 3 列
cut -d: -f3- /etc/passwd        # 取第 3 列到末尾
cut -d: -f-3 /etc/passwd        # 取开头到第 3 列
```

一般配 `-f` 的几个模式：
```
-f1        单列
-f1,3,5    多个离散列（逗号分隔）
-f1-3      连续范围
-f3-       从某列到末尾
-f-3       开头到某列
```

### 2. 按字符位置提取 `-c`

```bash
cut -c1-10 file.txt             # 每行的第 1 到第 10 个字符
cut -c5 file.txt                # 每行的第 5 个字符
cut -c1,3,5 file.txt            # 每行的第 1、3、5 个字符
cut -c5- file.txt               # 从第 5 个字符到行尾
```

注意：`-c` 统计的是**字符数**（UTF-8 下中文算一个字符），不是字节数。

### 3. 按字节位置提取 `-b`

```bash
cut -b1-10 file.txt             # 按字节位置取
```

> ⚠️ `-b` 和 `-c` 在处理纯 ASCII 文本时一样，但涉及多字节字符（中文、emoji）时会不同。`-c` 是真正"人看到的第几个字符"，`-b` 是"底层第几个字节"。

### 4. 指定输出分隔符 `--output-delimiter`

```bash
# 输入的列是逗号分隔，但我想用制表符输出
cut -d, -f1,3 --output-delimiter=$'\t' data.csv
```

### 5. 补集 `--complement`

```bash
# 取除了第 1 列以外的所有列
cut -d: -f1 --complement /etc/passwd
# 等价于：删除第一列，显示其余
```

## 场景驱动

### 1. 提取 CSV 的特定列

```bash
# data.csv: id,name,email,department
# 只要 id 和 email（第 1 和第 3 列）
cut -d, -f1,3 data.csv
```

### 2. 提取 ps 输出中的 PID 和命令

```bash
# ps aux 的列是用空白分隔的，但列宽不固定——cut 不好处理
# 这种情况应该用 awk：awk '{print $2, $11}'

# 但对于等宽列输出（如 ps -ef），cut -c 很合适：
ps -ef | cut -c1-8,49-
# 取 PID（固定在第 1-8 字符位置）和 CMD（从第 49 字符开始）
```

### 3. 从日志中提取时间戳

```bash
# 日志格式固定：前 19 个字符是时间
# 2025-07-13 14:30:15 ERROR ...
cut -c1-19 app.log

# 看看有哪些不同的日期
cut -c1-10 app.log | sort -u
```

### 4. 只看文件权限（ls -l 的第一列）

```bash
ls -l | cut -d' ' -f1
# drwxr-xr-x
# -rw-r--r--
```

## cut vs awk：什么时候用哪个

| 场景 | cut | awk |
|------|-----|-----|
| 按单个字符分隔提取列 | ✅ 首选 | 也行 |
| 按多字符分隔提取列 | ❌ 不支持 | ✅ `-F'::'` |
| 按固定字符位置提取 | ✅ `-c` | 麻烦（`substr`） |
| 按空白（任意空格/制表符）分隔 | ⚠️ 不太方便 | ✅ 默认按空白分隔 |
| 需要条件判断 + 提取 | ❌ 不支持 | ✅ `/error/ {print $1}` |
| 需要计算/统计 | ❌ 不支持 | ✅ |

> 💡 一句话：**纯切割用 cut，需要任何"逻辑"用 awk。**

---

## 新手踩坑总结

- **坑一：`-d` 只能接单个字符。** 多字符分隔符要换 awk。
- **坑二：用 cut 处理变宽字段。** `ps aux` 的列之间空白数量不固定，cut 不好处理。用 awk 更合适。
- **坑三：`-f` 的列号从 1 开始，不是 0。** `cut -d, -f1` 是第一列。
- **坑四：`-c` 统计字符数不是字节数。** 处理中文没问题；处理二进制文件——别用 cut。

---

## 最后

cut 是那种"简单的需求用它刚好，复杂的需求它不会"的命令——这恰恰是它的优点。它从不假装自己会做更多的事。当你只需要从文件里剪出一列时，别习惯性地去开 awk——`cut -d, -f3` 三个参数，干净利落。
