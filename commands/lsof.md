# 为什么 lsof 很强，但大多数人只知道 `lsof -i`？

> 很多人排查"端口被谁占了"时才想起 lsof，用完就忘。其实 lsof 是 Linux/Unix 里最被低估的诊断工具——它回答的不只是"谁在用端口"，而是"哪个进程打开了什么资源"，文件、socket、管道、设备，全在它的视野里。

## 一、你会遇到的场景

某天你删了一个日志文件，但磁盘空间没释放。`df -h` 还是 95%，可 `du -sh /var/log` 明明变小了。

新手的反应：怀疑人生，重启机器。

而真正理解 lsof 的人，会这样查：

```bash
lsof | grep deleted
```

立刻找到那个"已删除但仍被进程持有"的文件——进程还在往里写，`rm` 只是删了目录条目，磁盘空间要等进程关闭文件才释放。找到进程后 `kill` 或重启服务，磁盘瞬间回收。

**这就是 lsof 的核心价值：列出进程打开的文件/资源——文件、socket、管道、设备，一切皆文件。** 它的全称是 **l**i**s**t **o**pen **f**iles，但"文件"在这里是 Unix 哲学意义上的——万物皆文件。

## 二、它是怎么工作的——IO 模型

lsof 的本质是 `内核打开文件表 → 按维度筛选 → 格式化输出`：

```
内核打开文件表（/proc/*/fd 或内核数据结构）
    │
    ↓ 按进程筛选：-p PID（特定进程）/-c ssh（特定命令名）
    │  按用户筛选：-u root
    │  按文件筛选：-i :8080（网络端口） /some/path（具体文件）
    │  按文件系统筛选：+D /var/log（某个目录树）
    │
    ↓ 显示字段（默认全部）：COMMAND、PID、USER、FD、TYPE、SIZE、NAME
    │
stdout：每行一个打开的文件描述符
```

> 💡 lsof 的输出行数通常超出你的预期——一个普通进程可能打开了几十个文件（库文件、配置文件、socket、管道）。但你不必看全部——筛选才是 lsof 的正确打开方式。**不加筛选就跑 lsof，就像不加 WHERE 就跑 SQL 查询。**

## 三、语法骨架——先把句型刻进脑子里

```
lsof  [筛选条件]  [文件/路径]
       ───┬───     ──┬──
         谁？         什么？
```

属于**骨架模式 D**：`查询 + 展示`。和 ss、ps 同族。lsof 的特色在于它支持两种筛选方式：从"谁打开的"出发，或者从"打开了什么"出发。

⚠️ **在讲具体能力之前，先排一个新手几乎必踩的雷：**

### 雷一：不加筛选直接跑 `lsof`，输出爆炸

```bash
# ❌ 不要这样做：LANG=C lsof | wc -l   可能几千上万行
lsof

# ✅ 永远带筛选条件
lsof -p $$              # 只看当前 shell
lsof -i :8080           # 只看 8080 端口
lsof /var/log/syslog    # 只看谁打开了这个文件
```

不加筛选的 lsof 会把所有进程的所有打开文件全列出来——在服务器上可能是几万行。**lsof 的正确用法是"带着问题来"，不是"先看看有什么"。**

## 四、核心能力逐轴拆解

lsof 的能力沿 4 个轴展开——你既可以从"谁"出发，也可以从"什么"出发。

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 进程轴 | 哪个进程/命令？ | `-p PID`、`-c ssh` |
| 用户轴 | 哪个用户？ | `-u root`、`-u ^root`(排除) |
| 资源轴 | 什么类型的资源？ | `-i`(网络)、`-U`(UNIX socket)、具体路径 |
| 网络轴 | 哪个端口/协议？ | `-i :8080`、`-i TCP`、`-i @host` |

---

### 轴 1：进程轴——"某个进程打开了什么？"

> 场景：你想知道 nginx 打开了哪些文件——配置文件、日志文件、socket。

```bash
# 按 PID
lsof -p 12345

# 按命令名（会匹配所有该命令的进程）
lsof -c nginx

# 多个进程
lsof -p 1234,5678
```

---

### 轴 2：用户轴——"某个用户打开了什么？"

> 场景：你想看 root 用户打开了哪些文件。

```bash
# root 用户
lsof -u root

# 排除 root（^ 表示 NOT）
lsof -u ^root

# 当前用户
lsof -u $(whoami)
```

---

### 轴 3：资源轴——"谁打开了这个文件/目录？"

> 场景：你想卸载一个 U 盘，但系统说 `device is busy`。谁在用？

```bash
# 谁打开了我这个文件？
lsof /var/log/syslog

# 谁在用这个目录（或目录下的任何文件）？
lsof +D /mnt/usb

# 谁打开了已删除但未释放的文件？
lsof | grep deleted

# 看某个进程打开了哪些网络连接
lsof -p <PID> -i
```

> ⚠️ **`lsof +D` 会递归遍历目录下所有文件，大目录可能很慢。** 如果只需要看目录本身（不递归），用 `lsof /path/to/dir`（不加 `+D`）。

---

### 轴 4：网络轴——"谁在用这个端口？"

> 场景：这是 lsof 最高频的使用场景——端口被占用了。

```bash
# 谁在监听 8080 端口？
lsof -i :8080

# 只看 TCP
lsof -i TCP

# 只看 TCP 的 22 端口
lsof -i TCP:22

# 谁在连接特定主机？
lsof -i @192.168.1.100

# 列出所有网络连接
lsof -i

# 组合：某用户的所有网络连接
lsof -u www-data -i
```

> 💡 在 Linux 上 `ss -tlnp` 更快更现代；在 macOS 上 `lsof -i` 是查端口的主力。两个命令互补：ss 以 socket 为中心，lsof 以进程为中心。

## 五、Pipeline 组合——lsof 的进程级透视

lsof 可以和其他进程/网络工具组合：

```
lsof -i TCP:8080         （找到占用 8080 的进程 PID）
    │  输出：进程名 + PID
    ↓
awk '{print $2}'          （提取 PID 列）
    │
    ↓
kill                      （终止进程——⚠️ 确认后再操作）
```

```bash
# 找到占用 8080 端口的进程并列出详细信息
lsof -i :8080 | awk 'NR>1 {print $2}' | xargs ps -p
```

> ⚠️ 不要直接 pipe 到 `kill`——先看清楚是哪个进程，确认不会误杀再手动 kill。

## 六、真实排障全流程复盘

回到开头的场景：删了日志文件但磁盘没释放。

**第一步：找"已删除但仍打开"的文件**
```bash
lsof | grep deleted
```

**第二步：确认——是哪个进程、文件多大**
```bash
lsof | grep deleted | awk '{print $1, $2, $NF, $(NF-1)}'
# 输出：进程名 PID 文件名 大小
```

**第三步：看看文件在 /proc 里的大小**
```bash
ls -l /proc/<PID>/fd/ | grep deleted
```

**第四步：处理——重启/重载该进程**
```bash
# 如果是通过 systemd 管理的
systemctl restart <service>
# 或者重载（让进程重新打开日志文件）
kill -HUP <PID>
```

**第五步：复查——磁盘回来了吗？**
```bash
df -h /
```

## 七、踩坑清单

- **坑一：`lsof` 不加筛选输出爆炸** → 永远带 `-p`、`-i`、`-u` 或文件路径。lsof 不是"随便看看"的工具。
- **坑二：`lsof +D /` 会扫描整个文件系统** → `+D` 递归遍历目录树，在大目录上可能几分钟不返回。非必要不用 `+D`。
- **坑三：网络信息里端口号可能显示为服务名** → 加 `-P`（不解析端口名）和 `-n`（不解析主机名）看数字，更快更清晰：`lsof -i -P -n`。
- **坑四：非 root 看不到其他用户的进程** → lsof 很多输出需要 root 权限。排查系统级问题时先 sudo。
- **坑五：`lsof` 和 `ss` 对同一端口的输出格式不同** → lsof 以进程为中心（每个 FD 一行），ss 以 socket 为中心。选哪个取决于你从"进程"出发还是从"连接"出发。

## 八、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 查端口/网络连接 | `ss` (Linux) / `lsof -i` (macOS) | ss 更快更现代，但 macOS 只有 lsof |
| 查进程打开的文件 | lsof | 这正是 lsof 的核心设计 |
| 查"已删除但未释放"的文件 | lsof | 唯一能直接看到 deleted 标记的工具 |
| 查文件系统 IO 性能 | `iotop` / `iostat` | lsof 看"打开了什么"，不看"读写了多少" |
| 查系统调用层面的文件操作 | `strace` | lsof 看快照，strace 追踪过程 |

---

> **核心观点：** 学 lsof 不是为了背参数，而是理解它的 **IO 模型**（内核打开文件表 → 按维度筛选 → 格式化输出）和 **4 个能力轴**（进程、用户、资源、网络）。lsof 的筛选条件可以自由组合——它本质是一个"打开文件"维度的搜索引擎。
>
> 下次遇到"不知道谁在用这个文件/端口/目录"，你的第一反应该是 lsof 了。
