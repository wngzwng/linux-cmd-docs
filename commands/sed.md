# 为什么 sed 很强，但大多数人只会 `s/old/new/`？

> 很多人用了好几年 Linux，sed 永远只会一种用法——`sed 's/foo/bar/g'` 做全局替换，再复杂一点就换 Python 了。其实 sed 是一台流编辑器，`s///` 只是它十几个命令中的一个。

## 一、你会遇到的场景

某天你要改一个配置文件，把里面所有 `port 8080` 改成 `port 9090`，而且只改 `[server]` 段落里的，别的段落里的 `8080` 不能动。

新手的反应往往是：用 vim 打开，肉眼找到 `[server]`，手动改那几行——50 行的配置文件还行，500 行就崩溃了。或者写个 Python 脚本：读文件、状态机、正则替换、写文件——十分钟过去了。

而真正理解 sed 的人，一行搞定：

```bash
sed -i '' '/\[server\]/,/^\[/ s/port 8080/port 9090/' config.ini
```

一秒出结果，只改目标段落。

**这就是 sed 的核心价值：对文本流按地址筛选后执行编辑命令——替换、删除、插入、打印，全自动完成。** 它不是"查找替换工具"，它是一个可以编程的流编辑器。

## 二、它是怎么工作的——IO 模型

sed 的本质不是 `s/old/new/g`，而是 `逐行读入 → 地址匹配 → 命令执行 → 默认输出`：

```
输入文件（或 stdin）
    │
    ↓ 逐行读入，存入 pattern space（模式空间）
    │
    ↓ 按地址（address）匹配：这一行在操作范围内吗？
    │   ├─ 无地址 → 所有行都匹配
    │   ├─ 行号：3、$（最后一行）
    │   ├─ 正则：/pattern/
    │   └─ 范围：/start/,/end/（从匹配 start 的行到匹配 end 的行）
    │
    ↓ 匹配成功 → 执行命令序列（s/d/p/i/a/c...）
    │  匹配失败 → 跳过命令，直接到输出
    │
    ↓ 默认行为：将 pattern space 打印到 stdout
    │  （-n 选项抑制此行为——只有显式 p 命令才会输出）
    │
    ↓ 清空 pattern space，读下一行
    │
输出：被修改过的文本流
```

> 💡 理解了这个模型，`sed -n '/error/p'` 就很容易懂了：`-n` 抑制默认输出，`/error/` 是地址（匹配含 error 的行），`p` 是命令（print）。合起来就是"只打印含 error 的行"——和 `grep error` 效果相同，但机制不同：grep 是过滤器，sed 是"选择性打印"。

还有一个进阶概念：**hold space（保留空间）**。可以把它想象成一个剪贴板——`h` 把当前行复制到剪贴板，`g` 从剪贴板粘贴回来，`H` 追加到剪贴板，`G` 从剪贴板追加到当前行。多行操作（比如两行互换、段落重组）靠的就是 pattern space + hold space 的配合。

## 三、语法骨架——先把句型刻进脑子里

```
sed  [选项]  '[地址]命令'  [文件...]
     ─┬─     ─────┬────    ──┬──
     选项槽         编辑槽       输入槽
```

属于**骨架模式 E**：`输入 → 转换 → 输出`。和 awk 同族，但 sed 更轻量——它的"转换规则"是地址+命令，不是编程语言。

⚠️ **在讲具体能力之前，先排三个新手几乎必踩的雷：**

### 雷一：BSD sed 的 `-i` 必须带备份后缀！

```bash
# ❌ GNU sed 上能跑，BSD sed（macOS）上报错：
sed -i 's/foo/bar/g' file.txt
# → sed: -i may not be used with stdin 或直接报错

# ✅ 跨平台安全写法：给 -i 指定备份后缀
sed -i '.bak' 's/foo/bar/g' file.txt    # 生成 file.txt.bak 作为备份
sed -i '' 's/foo/bar/g' file.txt        # BSD: 空字符串 = 不备份（⚠️ 有风险）

# ✅ 最安全的写法：先不用 -i，确认结果没问题再加
sed 's/foo/bar/g' file.txt | head       # 第一步：预览
sed -i '.bak' 's/foo/bar/g' file.txt    # 第二步：确认无误后执行
```

> ⚠️ `-i ''`（不备份）有风险——如果磁盘满了，你的原文件可能损坏。生产环境强烈建议用 `-i '.bak'` 保留备份。另外 `-i` 会直接覆盖原文件，是不可逆操作——**永远先跑一遍不带 `-i` 的预览版。**

### 雷二：用单引号，别用双引号——shell 会先吃掉 `$` 和 `\`

```bash
# ❌ 双引号里 $1 和 \1 都会被 shell 解释
sed "s/\(hello\)/\1 world/"   # shell 把 \1 展开成什么？不知道！

# ✅ 单引号保护一切
sed 's/\(hello\)/\1 world/'
```

规则和 awk 一样：**sed 程序用单引号包裹。** 需要插入 shell 变量时才用双引号，但此时 `$` 和 `\` 要加倍小心。

### 雷三：分隔符不一定是 `/`——处理路径时换分隔符少写一堆反斜杠

```bash
# ❌ 路径里有 /，每个都要转义——读起来像栅栏
echo "/home/user/docs" | sed 's/\/home\/user/\/opt\/backup/'

# ✅ 换一个分隔符，比如 # 或 |
echo "/home/user/docs" | sed 's#/home/user#/opt/backup#'
```

`s` 命令的第一个字符就是分隔符——`s/.../.../`、`s#...#...#`、`s|...|...|` 都合法。**处理文件路径、URL 时，用 `#` 或 `|` 做分隔符可以让命令可读性翻倍。**

## 四、核心能力逐轴拆解

sed 的能力沿 4 个轴展开。不要记命令字母——每个轴回答一个具体问题，各轴正交，自由组合。

| 能力轴 | 问题 | 核心机制 |
|--------|------|---------|
| 地址轴 | 对哪些行操作？ | 行号、`$`、`/regex/`、范围 `,/regex/` |
| 编辑轴 | 对这些行做什么？ | `s`(替换)、`d`(删除)、`p`(打印)、`i`(插入)、`a`(追加)、`c`(整行替换) |
| 标志轴 | 替换时怎么控制范围？ | `g`(全局)、`N`(第N次)、`p`(同时打印)、`i`/`I`(忽略大小写) |
| 控制轴 | 怎么改变默认行为？ | `-n`(抑制自动打印)、`-E`(扩展正则)、`!`(取反地址)、`;`/`-e`(多命令) |

---

### 轴 1：地址轴——"对哪些行操作？"

> 场景：配置文件第 12 行是端口号，你只改这一行；或者你只改 `[database]` 段落里的配置。

```bash
# 只改第 3 行
sed '3s/foo/bar/' file.txt

# 只改第 5 到第 10 行
sed '5,10s/foo/bar/' file.txt

# 改最后一行
sed '$s/foo/bar/' file.txt

# 改匹配正则的行
sed '/server/s/8080/9090/' config.txt

# 改从 START 到 END 的范围（段落操作！）
sed '/\[server\]/,/^\[/s/port 8080/port 9090/' config.ini

# 取反：改所有"不是注释"的行
sed '/^#/!s/foo/bar/' config.txt

# 隔行处理：改所有奇数行（1,3,5...）
sed '1~2s/foo/bar/' file.txt
# > 💡 1~2 是 GNU sed 扩展（first~step），BSD sed 不支持此语法，兼容写法用 awk
```

地址决定了命令的"作用域"。**地址是 sed 和普通"查找替换"最本质的区别。** 没有地址时命令作用于所有行；有了地址，sed 就变成了一个精确的文本手术刀。

---

### 轴 2：编辑轴——"对这些行做什么？"

> 场景：不只是替换——你还要删除空行、在文件头插入一段注释、把某行整个替换掉。

```bash
# d: 删除——去掉所有空行
sed '/^$/d' file.txt

# p: 打印（配合 -n）——只显示第 10~20 行
sed -n '10,20p' file.txt

# i: 在匹配行之前插入
sed '/\[server\]/i\
# === Server Config ===' config.ini

# a: 在匹配行之后追加
sed '/\[server\]/a\
# Last modified: 2024-01-01' config.ini

# c: 整行替换——把匹配行整个换成新内容
sed '/deprecated/c\
# This section has been removed' config.ini
```

> ⚠️ **`a`、`i`、`c` 命令的语法和 `s` 完全不同。** `s` 命令用 `/` 分隔，一行写完；`a`/`i`/`c` 后面跟的是文本，需要反斜杠+换行来分隔。这在命令行里很别扭——对于复杂的插入操作，更推荐用 `sed -f script.sed` 把命令写进文件。

---

### 轴 3：标志轴——"替换时怎么控制范围？"

> 场景：一行里有多个 `foo`，你只改第二个；或者你想边改边打印被改的行。

```bash
# g: 全局替换（一行里所有匹配都改）
echo 'foo foo foo' | sed 's/foo/bar/g'
# → bar bar bar

# N: 只改第 N 次出现
echo 'foo foo foo' | sed 's/foo/bar/2'
# → foo bar foo

# p: 替换成功后同时打印（配合 -n 只看被改的行）
sed -n 's/foo/bar/gp' file.txt

# i/I: 忽略大小写（BSD sed 支持 I 标志）
sed 's/error/ERROR/Ig' app.log
```

> 💡 `g` 和 `p` 是最常用的两个标志。`N`（第 N 次匹配）被严重低估——一行里有多个相同字段时（比如一行里多个数字），精确替换第几个非常有用。而 `i`/`I` 标志在 BSD sed 和 GNU sed 上都可用，处理大小写不敏感场景比用 `[Ee][Rr][Rr][Oo][Rr]` 优雅得多。

---

### 轴 4：控制轴——"怎么改变 sed 的默认行为？"

> 场景：你要用扩展正则（`+`、`?`、`|` 不需要反斜杠），或者一次执行多条命令。

```bash
# -n: 抑制默认输出——没有 p 命令就什么都不打印
sed -n 's/foo/bar/p' file.txt   # 只打印被替换的行

# -E: 扩展正则（BRE → ERE）——不用再写一堆反斜杠
echo 'hello     world' | sed -E 's/hello[ ]+world/HI/'   # + 不用转义

# -e: 多条命令（或直接用 ; 分隔）
sed -e '/^#/d' -e '/^$/d' -e 's/foo/bar/' file.txt
sed '/^#/d; /^$/d; s/foo/bar/' file.txt   # 等价写法

# -f: 从文件读取命令——复杂脚本的推荐方式
sed -f cleanup.sed file.txt
```

> ⚠️ **sed 默认用 BRE（基本正则），不是 ERE。** 在 BRE 里 `+`、`?`、`|`、`()`、`{}` 都需要反斜杠转义才表示特殊含义。**养成习惯：能用 `-E` 就用 `-E`**，这样你的正则在 sed、grep -E、awk 之间行为一致，不用记两套规则。`-E` 在 BSD sed 上是标准选项，GNU sed 用 `-r`（`-E` 也逐步支持）。

## 五、Pipeline 组合——sed 的天然战场

sed 接受 stdin、输出到 stdout，天然适合站在管道中间：

```
cat access.log
    │  输出：原始日志
    ↓
sed -n '/500/p'         （过滤出 500 错误行）
    │  输出：只含 500 的行
    ↓
sed 's/.*from \(.*\) .*/\1/'   （提取 IP 地址部分）
    │  输出：每行一个 IP
    ↓
sort | uniq -c | sort -rn      （统计 + 排序）
```

```bash
sed -n '/ 500 /p' access.log | sed 's/.*from \([0-9.]*\).*/\1/' | sort | uniq -c | sort -rn | head -10
```

> 💡 这里能串起来的关键是：每一步 sed 的输出都是纯文本行，恰好是下一步期望的输入格式。尤其是第二个 sed，它只输出 IP（`\1`），把一整行日志压缩成一个 IP 地址——这就是 sed 在管道里最常做的事：**格式转换**。

**一个经典的生产级组合：预处理 + 替换 + 回写**

```bash
# 场景：清理配置文件——去掉注释和空行，再把所有 tab 换成空格
sed -E -e '/^[[:space:]]*#/d' -e '/^[[:space:]]*$/d' -e 's/\t/    /g' nginx.conf
```

sed 在这里做了三件事，但只需要一次文件扫描——因为命令是顺序执行在每一行上的，不是三遍文件。**理解"逐行+顺序执行命令"这个模型，你就明白为什么多个 `-e` 比多次管道快。**

## 六、真实排障全流程复盘

回到开头的场景：修改 `config.ini`，只改 `[server]` 段落里的端口号。

**第一步：定位——看看 `[server]` 段落在哪**
```bash
sed -n '/\[server\]/,/^\[/p' config.ini
```
`/\[server\]/,/^\[/` 是从 `[server]` 到下一个 `[` 开头的行（即这一个段落）。`-n` + `p` = 只打印这个范围，用来预览。

**第二步：预览——看看替换效果**
```bash
sed '/\[server\]/,/^\[/s/port 8080/port 9090/' config.ini | diff config.ini -
```
⚠️ 安全铁律：先用不带 `-i` 的版本，对比一下改了什么。`diff` 显示差异——你应该只看到 `[server]` 段落里的 `port` 行变了。

**第三步：备份后执行**
```bash
cp config.ini config.ini.bak
sed -i '' '/\[server\]/,/^\[/s/port 8080/port 9090/' config.ini
```
> `-i ''` 在 BSD sed 上是"不创建额外备份"（前面已手动备份了）。GNU sed 上 `-i` 不带参数即可，跨平台脚本写 `-i'.bak'` 最安全。

**第四步：复查——改对了吗？**
```bash
diff config.ini.bak config.ini
```

> 整个过程没有打开编辑器，没有手动找行号，全程靠地址+命令的组合完成定位→预览→执行→复查。

## 七、踩坑清单

- **坑一：`-i` 的行为 GNU 和 BSD 不一样** → GNU: `sed -i 's/.../'` 直接改；BSD/macOS: 必须带后缀 `sed -i '' 's/.../'` 或 `sed -i '.bak' 's/.../'`。跨平台脚本永远写 `-i'.bak'`。
- **坑二：BRE vs ERE——默认正则里 `+` 和 `?` 要转义** → `sed 's/a+/b/'` 匹配的是 `a` 后面跟一个字面加号，不是"一个或多个 a"。用 `-E` 切换到扩展正则，或者写成 `sed 's/a\+/b/'`（BRE 中 `\+` 表示一个或多个）。
- **坑三：`s` 默认只替换每行的第一次匹配** → 想替换整行里所有的，必须加 `g` 标志：`s/foo/bar/g`。这个坑几乎 100% 的新手都会踩一次。
- **坑四：反斜杠和 shell 的战争** → `sed 's/\(.*\)/\1/'` 在单引号里安全；但如果用了双引号，shell 会把 `\1` 吃掉的。记住：sed 程序用单引号。
- **坑五：`a`/`i`/`c` 命令的换行语法很难看** → 复杂编辑不要硬写在命令行里，写一个 `script.sed` 文件，用 `sed -f script.sed` 执行。
- **坑六：`-n` 忘加时 `p` 会印两次** → 默认输出一行 + `p` 命令又输出一行 = 重复。记住：`p` 配合 `-n` 用，`d` 单独用。
- **坑七：用 `/` 做分隔符时路径全是反斜杠森林** → 处理文件路径/URL，换分隔符：`s#/old/path#/new/path#`。

## 八、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 简单替换、按行号/正则删除 | sed | 这正是 sed 的设计领域——轻量、快速、管道友好 |
| 需要跨行累加、分组统计 | awk | sed 没有变量和数组，不能做算术聚合 |
| 只需要筛选行 | grep | grep 更快更简洁，不需要 sed 的编辑开销 |
| 复杂多行操作（段落重组、XML 解析） | Python / awk | sed 的 hold space 能做但可读性差，不是它的设计目标 |
| 处理 JSON / YAML / XML | jq / yq / xmllint | sed 不理解嵌套结构，改结构化数据不可靠 |
| 交互式编辑 | vim / nano | sed 是批处理工具，没有交互界面 |

## 九、换个命令你会了吗？

sed 属于**骨架模式 E**：`输入 → 转换 → 输出`。同一模式的命令还有：

- **awk**：sed 的大哥——`sed 's/foo/bar/'` ≈ `awk '{sub(/foo/, "bar"); print}'`，但 awk 多了变量、数组、算术能力，代价是更重
- **tr**：sed 的简化版——`tr 'a-z' 'A-Z'` ≈ `sed 'y/abcdefghijklmnopqrstuvwxyz/ABCDEFGHIJKLMNOPQRSTUVWXYZ/'`，但 tr 只能逐字符替换，没有正则
- **cut**：只提取列，不做编辑——`cut -d, -f1` 是只读的，sed 能改内容

学完 sed，你其实已经掌握了"地址→命令→流输出"这一类编辑器的核心思维。**下次遇到 vim 的 `:s/old/new/g` 命令，你会发现它们一脉相承——vim 的 ex 模式本质上就是 sed 的前身 ed 的交互版本。**

---

> **核心观点：** 学 sed 不是为了记住 `s/old/new/g` 这个固定写法，而是理解它的 **IO 模型**（逐行读入 → 地址匹配 → 命令执行 → 默认输出）和 **4 个能力轴**（地址、编辑、标志、控制）。一旦这两个立住了，任何"对文本做条件编辑"的需求你都能从轴里选出组合，填入骨架，命令自然生成。
>
> sed 是管道里的瑞士军刀——它不需要像 awk 那样写程序，也不像 grep 那样只能看不能改。它恰好站在"简单筛选"和"复杂计算"的中间，是文本流处理里最趁手的轻量工具。
>
> 你平时用 sed，是不是也停留在 `sed 's/foo/bar/g'` 的阶段？
