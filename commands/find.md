# find：按名字、时间、大小、权限筛选文件——从 `-name` 到 `-exec`

> 很多人用了好几年 Linux，find 永远只会一种用法——`find . -name "*.log"`，再复杂一点就放弃。其实 find 是一个文件系统查询引擎，它的强大不在于"找文件"，而在于"找到后做什么"。

## 一、你会遇到的场景

某天你收到磁盘告警：根分区使用率 95%。

新手的第一反应往往是 `cd` 进各个目录，挨个 `du -sh *`，一层层往下翻，运气不好的话能翻半小时。更糟的是，有些大文件藏在深处、名字毫无规律，手动翻根本找不到。

而真正理解 find 的人，只会敲一行：

```bash
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

几秒钟之后，所有大于 100MB 的文件列出来，元凶一目了然。

**这就是 find 的核心价值：在文件系统里按任意条件查找文件，并对结果执行操作。** 它不是"搜索文件名"的工具——它是一个文件系统查询引擎。

## 二、它是怎么工作的——IO 模型

find 的本质不是 `command + options`，而是 `文件树 → 遍历 → 过滤 → 动作 → 结果`：

```
文件系统（从你指定的目录开始）
    │
    ↓ 递归遍历：深度优先，逐个访问每个文件和子目录
    │
    ↓ 按条件过滤：名字对吗？类型对吗？大小对吗？时间对吗？
    │   条件之间默认是 AND 关系——多个条件叠加，范围越来越窄
    │
    ↓ 对匹配的文件执行动作：打印路径 / 删除 / 执行任意命令
    │
输出：执行动作后的结果（默认打印匹配的文件路径）
```

> 💡 理解了 IO 模型，`-type`、`-name`、`-size`、`-mtime`、`-delete` 这些参数就自然出现了——它们分别控制"过滤什么"和"对结果做什么"。**注意 find 默认就递归遍历，不需要 `-r` 参数（和 grep 不同）。**

## 三、语法骨架——先把句型刻进脑子里

```
find  [从哪里开始]  [按什么条件过滤]  [对结果做什么]
      ──┬──         ──────┬──────     ────┬───
      起点槽              条件槽            动作槽
```

属于**骨架模式 A**：`源 → 过滤 → 目标`。同一模式的命令还有 rsync。三个槽位线性展开，条件可以堆叠任意多个。

⚠️ **在讲具体能力之前，先排一个新手几乎必踩的雷：**

```bash
# ❌ 错误：-exec 忘了分号，语法直接报错
find . -name "*.log" -exec rm {}

# ✅ 正确：\; 是 -exec 动作的结束标志，必须带
find . -name "*.log" -exec rm {} \;
```

`-exec` 不经过 shell——它直接调用（exec）指定的程序。`{}` 是匹配文件的占位符，`\;` 告诉 find "命令到此结束"。分号前面加反斜杠是必须的——不加的话 shell 会把 `;` 当成命令分隔符吃掉。需要 shell 特性（管道、重定向）时用 `-exec sh -c '...' \;`。

## 四、核心能力逐轴拆解

find 的能力沿 7 个轴展开。不要背参数——每个轴回答一个具体问题，各轴正交，自由组合。

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 范围 | 从哪开始找？ | 路径参数、`-maxdepth`、`-mindepth` |
| 类型 | 找文件还是目录？ | `-type f`, `-type d`, `-type l` |
| 名称 | 叫什么？ | `-name`, `-iname`, `-regex` |
| 时间 | 什么时候改的/读的？ | `-mtime`, `-atime`, `-ctime`, `-mmin` |
| 大小 | 多大？ | `-size +100M`, `-size -10k` |
| 权限 | 谁可以读写？ | `-perm`, `-user`, `-group` |
| 动作 | 找到之后做什么？ | `-print`(默认), `-delete`, `-exec` |

---

### 轴 1：类型——"我在找文件还是目录？"

> 场景：你只想清理大文件，但目录会干扰你的判断。

```bash
# 只找文件
find /var/log -type f -size +10M

# 只找目录
find . -type d -name "*.old"

# 找符号链接（排查"这个 link 指向的文件还在吗？"）
find /var/log -type l
```

---

### 轴 2：名称——"它叫什么？"

> 场景：你记得有个文件叫 "report"，但不记得后缀也不记得大小写。

```bash
find . -name "report.pdf"          # 精确匹配
find /var/log -name "*.log"        # 通配符
find . -iname "report*"            # 忽略大小写
```

> 💡 `-name` 用的是 shell glob 模式（`*`、`?`、`[]`），不是正则。正则用 `-regex`（匹配完整路径）。

---

### 轴 3：时间——"什么时候改的？"

> 场景：磁盘告警，你想看看是不是最近的日志爆了；或者清理 30 天前的旧备份。

```bash
find /var/log -mtime -7                  # 最近 7 天修改的
find /var/log -name "*.log" -mtime +30   # 30 天前——该清理了
find /etc -mmin -10                      # 最近 10 分钟动过的
```

符号规则：`+n` = 超过 n，`-n` = 不到 n，`n` = 恰好 n。

> ⚠️ **ctime 不是"创建时间"！** ctime 是 inode 变更时间——权限变了、硬链接数变了、所有者变了都会更新。内容修改时间看 mtime。

---

### 轴 4：大小——"它占了多少空间？"

> 场景：磁盘满了，你怀疑是不是有超大日志文件或 core dump。

```bash
find / -type f -size +100M 2>/dev/null     # 磁盘杀手排查
find . -type f -size 0                      # 空文件
find . -type f -size +100M -size -500M      # 精确区间
```

> ⚠️ `-size` 不带单位时默认是 512 字节块（历史原因）。**始终带单位：`c`(字节), `k`(KB), `M`(MB), `G`(GB)。**

---

### 轴 5：权限——"谁可以读写它？"

> 场景：安全审计——找出所有"任何人可写"的目录。

```bash
# 任何人可写的文件
find /var/www -type f -perm -o=w

# 不属于当前用户的文件
find . -type f ! -user $(whoami)
```

> ⚠️ `-perm 777` 精确匹配 / `-perm -777` 全部设了 / `-perm /777` 任一设了——差一个符号结果完全不同。

---

### 轴 6：动作——"找到之后做什么？"

> 场景：这是 find 区别于 locate 的关键——find 能对找到的文件执行操作。

```bash
# 默认：打印路径
find . -name "*.log"

# ⚠️ 安全铁律——先预览，再执行！
find /tmp -name "*.tmp" -mtime +7 -print    # 第一步：看看要删什么
find /tmp -name "*.tmp" -mtime +7 -delete   # 第二步：确认后执行

# 批量压缩
find /var/log -name "*.log" -mtime +30 -exec gzip {} \;

# \; vs + 的区别
find . -name "*.log" -exec ls -lh {} \;   # 逐个执行（慢但灵活）
find . -name "*.log" -exec ls -lh {} +    # 批量执行（快）
```

---

### 轴 7：范围——"从哪开始找？"

> 场景：只想在当前目录找，不递归；或者同时搜多个目录。

```bash
find . -maxdepth 1 -name "*.txt"     # 只搜本层
find /var/log /opt/app/logs -name "*.log"   # 同时搜多个目录
```

> 💡 `-maxdepth` 是 GNU 扩展，BSD find（macOS）也已支持。

## 五、真实排障全流程复盘——磁盘告警

**第一步：定位——找出系统中的"空间大户"**

```bash
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

用了范围轴（`/`）、类型轴（`-type f`）、大小轴（`-size +100M`）、动作轴（`-exec ls -lh`）。`2>/dev/null` 吞掉权限报错。

**第二步：聚焦——是不是 /var/log 在失控增长**

```bash
find /var/log -type f -size +10M -ls
```

**第三步：预览——在动手前看看有哪些**

```bash
find /var/log -name "*.log" -mtime +30 -print
```

**第四步：执行——清理 30 天前的旧日志**

```bash
find /var/log -name "*.log" -mtime +30 -delete
```

**第五步：复查**

```bash
df -h /
```

> 整个过程没有手动进任何一个目录，全程靠 find 的条件组合完成定位→聚焦→预览→执行→复查。

## 六、踩坑清单

- **坑一：ctime ≠ 创建时间** → 文件内容修改看 mtime，inode 变更才看 ctime
- **坑二：-exec 忘了 `\;` 直接报错** → `\;` 是结束标志，不是随手的习惯
- **坑三：-delete 前不确认** → 先用 `-print` 或 `-ls` 看一眼
- **坑四：不加 `-type f` 误匹配目录** → `-delete` 可删空目录，`-exec rm -rf` 会递归删除非空目录
- **坑五：`-size` 不带单位** → 默认 512 字节块，数字完全不对。始终带单位
- **坑六：`-name` 用正则** → `-name` 是 shell glob，正则用 `-regex`

## 七、什么时候该换工具

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 按文件名快速查找 | `locate` | 数据库查询，比 find 快百倍 |
| 搜索文件内容 | `grep -r` | 搜文件名用 find，搜内容用 grep |
| 看某目录的磁盘占用 | `du -sh` | find 不擅长做加和统计 |
| 实时监控文件变化 | `inotifywait` | find 是快照式查找 |

## 八、换个命令你会了吗？

find 属于**骨架模式 A**：`源 → 过滤 → 目标`。同一模式的命令还有：

- **rsync**：同步文件的"源 → 过滤 → 目标"——指定源路径、包含/排除规则、目标路径，和 find 的句型完全一致

学完 find，你其实已经掌握了"源→过滤→目标"这一类命令的语法骨架。

---

> **核心观点：** 学 find 不是为了记住 `-name -mtime -size -delete` 这些字母，而是理解它的 **IO 模型**（文件树 → 遍历 → 过滤 → 动作）和 **7 个能力轴**。一旦这两个立住了，任何"找文件"的需求你都能从轴里选出组合，填入骨架，命令自然生成。
