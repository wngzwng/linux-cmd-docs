
# free：内存够不够——别看 free 列，看 available

如果你收到"内存不足"的告警，第一反应是 `free` 看一眼。但 free 的输出里有一列叫 "free"——很多人盯着它，发现只有几百 MB，慌了。实际上可能在它旁边，"available" 列显示着几个 GB。

这就是 Linux 内存管理的反直觉之处。本文帮你搞清楚：你看完 free 后应该担心哪一列。

---

## 场景引入：free 列只有 200MB 了，但系统没卡

```bash
free -h
#               total   used    free    shared  buff/cache   available
# Mem:           15G    10G     200M     500M        4.7G        4.3G
```

新手看到 `free: 200M`，开始紧张："我 15GB 内存只剩 200MB 了！"

但 `available: 4.3G` 在告诉你：别急，还有 4.3GB 可以用的。那 `buff/cache` 里的 4.7GB 大部分随时可以被回收。

> 💡 **Linux 会尽可能地用空闲内存做缓存。** 这 4.7GB 的 buff/cache 不是"被占了"，是"先借去用着，等你需要时马上还"。

---

## 核心概念：free 的五列分别是什么

| 列 | 含义 | 该担心吗 |
|---|---|---|
| `total` | 物理内存总量 | 看规模 |
| `used` | 已用 = total - free - buff/cache | 不用太担心 |
| `free` | 完全空闲的内存 | **不要盯着看！** |
| `buff/cache` | 被内核借去当缓存的内存 | 可回收，不算"占用" |
| `available` | **实际可用**内存（含可回收缓存） | **你要看的就这一列** |

> ⚠️ 记忆法则：**`free` 是假象，`available` 是真相。** 前者告诉你"完全没被碰过的内存有多少"，后者告诉你"如果需要，有多少内存可以立刻被分配"。

---

## 核心参数

```bash
free -h           # 人类可读格式（最常用）
free -m           # 以 MB 为单位
free -g           # 以 GB 为单位
free -s 2         # 每 2 秒刷新一次——持续监控
free -s 2 -c 5    # 每 2 秒刷新，一共 5 次
```

## 场景驱动

### 1. 收到内存告警：快速判断严重程度

```bash
free -h
# 看 available 列
# available < 10% total → 严重，需要扩容或杀进程
# available > 20% total → 暂时安全，但找原因
# available > 50% total → 告警可能是误报
```

### 2. 持续监控内存变化

```bash
# 每 2 秒刷新，观察内存波动趋势
free -h -s 2
# 配合跑你的任务，看看内存是被慢慢吃掉的还是突然暴增
```

### 3. 在脚本中提取可用内存

```bash
# 提取 available 的数值（人类可读不行，用 -m）
AVAILABLE_M=$(free -m | awk '/^Mem:/{print $7}')
echo "可用内存: ${AVAILABLE_M}MB"
```

### 4. 同时看 swap 使用情况

```bash
free -h
# 输出有两行：Mem 和 Swap
# Swap used > 0 不一定是坏事——但 used 持续增长且接近 total 就有问题
```

## 新手踩坑总结

- **坑一：盯着 `free` 列看。** 这是最经典的误区。Linux 的 buff/cache 是预借的内存，随时可还——真正要看的是 `available`。
- **坑二：看到 swap 用了就觉得内存不够。** 少量 swap 使用是正常的（内核会把一些极少访问的页面换出去）。要担心的是 swap used 持续增长。
- **坑三：`free -h` 的数值是四舍五入。** `4.3G` 可能实际是 4.34G。做精确脚本判断用 `-m`。
- **坑四：不清楚 total 比物理内存小。** 内核会预留一部分内存自用，`free` 显示的 total 比实际插的内存条容量略小。

## 什么时候换工具

| 需求 | free 行不行 | 替代方案 |
|------|------------|---------|
| 快速看内存概况 | 行 | — |
| 实时交互监控（带进程列表） | 不行 | `top` 或 `htop` |
| 查看某个进程的内存详情 | 不行 | `cat /proc/<PID>/status`、`pmap` |
| 内存泄漏分析 | 不行 | `valgrind`、`heaptrack` |

---

## 最后

`free` 的输出里藏了一个心理陷阱：一列叫 `free`，让你误以为只有这么多。Linux 内核比大多数人会管内存——它把空闲内存借去当缓存，等你需要时再要回来。你唯一需要关心的，是最后一列 `available`。
