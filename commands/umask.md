
# umask：你的文件一创建就被"减掉"了哪些权限——但你可能从没注意过

如果你在 Linux 上创建一个新文件，它自动就有了一套默认权限。用 `touch test.txt && ls -l test.txt`，你会看到类似 `-rw-r--r--` 的输出。你从来没手动设置过权限，是谁决定的？

答案是 **umask**。它在你背后默默工作了无数年，但大多数人从未注意过它的存在——直到某天创建了一个文件，发现"怎么别人读不了"，才开始查原因。

---

## 场景引入：脚本创建的文件总是"别人读不了"

你的同事写了个日志清理脚本，每天生成报告：

```bash
#!/bin/bash
echo "清理完成: $(date)" > /var/log/cleanup/report.txt
```

但第二天，另一个同事（不是文件所有者）想看报告，却被告知 Permission denied。

你查看文件权限：

```bash
ls -l /var/log/cleanup/report.txt
# -rw------- 1 root root 30 Jul 14 09:00 report.txt
```

`600`（所有者读写，其他人什么都干不了）。为什么不是常见的 `644`？

因为脚本运行时 umask 设置成了 `077`——它从新建文件的默认权限里"减掉"了组和其他人的所有权限。

---

## 核心概念：umask 是一个"权限减法过滤器"

umask 的核心逻辑：**每当进程创建一个新文件或目录，系统拿默认权限减去 umask 值，得到最终权限。**

公式：

```
新文件默认权限 = 666 - umask
新目录默认权限 = 777 - umask
```

> ⚠️ 注意：umask 只影响**新创建**的文件和目录。已存在的文件不受 umask 影响——要改使用 `chmod`。

---

## 先排雷：umask 不是简单的减法

```bash
umask 022     # 常见默认值
# 新文件：666 - 022 = 644  (rw-r--r--)
# 新目录：777 - 022 = 755  (rwxr-xr-x)
```

看起来像是直接减法，但实际上它做的是**按位屏蔽**。`022` 意味着："把组和其他人的写权限(2)屏蔽掉。"

```
666 = 110 110 110  (rw-rw-rw-)
022 = 000 010 010  (屏蔽组写 和 其他人写)
结果 = 110 100 100 = 644  (rw-r--r--)
```

> 💡 文件默认就是 666（无执行权限），因为大多数文件不需要执行权限。目录默认是 777（需要执行权限才能 `cd` 进去）。

## 核心能力逐层拆解

### 1. 查看当前 umask

```bash
umask              # 输出：0022（4 位，第一位是特殊权限位）
umask -S           # 符号形式：u=rwx,g=rx,o=rx
```

### 2. 设置 umask

```bash
umask 022          # 数字形式——推荐
umask u=rwx,g=rx,o=rx   # 符号形式——更直观但更啰嗦
```

常见 umask 值及其效果：

| umask | 新文件权限 | 新目录权限 | 适用场景 |
|-------|-----------|-----------|---------|
| `022` | 644 (rw-r--r--) | 755 (rwxr-xr-x) | 通用默认值 |
| `002` | 664 (rw-rw-r--) | 775 (rwxrwxr-x) | 团队共享目录 |
| `077` | 600 (rw-------) | 700 (rwx------) | 私密文件/安全脚本 |
| `027` | 640 (rw-r-----) | 750 (rwxr-x---) | 同组可读，其他人不可 |

### 3. 临时修改（不永久生效）

```bash
# 仅在当前 shell 会话生效
umask 077
touch private.txt
# 创建的 private.txt 只有所有者能访问
```

### 4. 永久修改

```bash
# 写入 shell 配置文件
echo "umask 022" >> ~/.bashrc

# 或系统级别（影响所有用户）
# /etc/profile 或 /etc/login.defs
```

## 场景驱动

### 1. 团队共享项目：让组员都能写

```bash
# 设置 umask，让同组成员能写新创建的文件
umask 002
mkdir /opt/team-project/new-feature/
touch /opt/team-project/new-feature/README.md
ls -la  # 新文件权限为 664，目录为 775
```

### 2. 安全脚本：创建的临时文件不能被别人看

```bash
#!/bin/bash
# 敏感操作——临时文件只能自己看
umask 077
TMPFILE=$(mktemp)
echo "password=secret123" > "$TMPFILE"
# 其他用户读不了这个文件
```

### 3. Web 应用部署：确保新上传文件权限正确

```bash
# 在应用的启动脚本里设置
umask 022
# 确保应用创建的所有文件默认为 644，目录为 755
```

## 新手踩坑总结

- **坑一：不知道 umask 的存在。** 创建的文件权限不对，第一反应是"操作系统的 bug"，其实是 umask 设得太严。
- **坑二：以为 `umask` 改了已存在文件的权限。** umask 只管新建，不管已有。改现有文件的权限用 `chmod`。
- **坑三：把 umask 设成 `777`。** 这会让所有新建文件权限变成 000——谁也读不了写不了。
- **坑四：在 shell 里临时设 umask，忘了一个新 shell 就恢复默认。** 永久生效要写进 `.bashrc`。
- **坑五：混淆 umask 的作用域。** 每个进程有自己的 umask。子进程继承父进程的 umask。

---

## 最后

umask 的存在感低到离谱——很多人用了十年 Linux 从没手动设过它。但这不代表它不重要：它决定了你创建的一切文件的"出生权限"。当你的脚本生成的日志别人读不了、Web 应用上传的文件权限不对——别急着改 `chmod`，先看看 `umask`。
