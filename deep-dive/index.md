# deep-dive：不只是会用，是理解它们怎么工作的

`commands/` 里的文档教你**用对**——什么场景敲什么命令，每个参数干什么。

这里不一样。这里每一篇都从一个问题开始：

> 「你每天都在用这个命令，但如果让你解释『当你敲下回车时究竟发生了什么』，你能说清楚吗？」

---

## 这些命令为什么值得深入

它们不是简单的「工具」，每一个都是一套**设计精巧的子系统**：

| 命令 | 表面身份 | 本质 |
|---|---|---|
| git | 版本控制 | 内容寻址的文件系统 |
| nvim | 文本编辑器 | 可编程的终端 UI 框架（Lua API + 事件驱动） |
| docker | 容器引擎 | OCI 运行时栈（分层镜像 + namespace/cgroups 隔离） |
| tmux | 终端复用器 | client-server 会话管理器 |
| systemctl | 服务管理 | 依赖拓扑驱动的进程生命周期管理器 |
| ssh | 远程登录 | 加密隧道引擎 + 多路复用协议 |

理解了本质，你就不是「背参数」而是在「推理用法」。新的场景出现时，你能自己猜出该怎么做——因为你的行为逻辑是从内部模型推导出来的，不是靠记忆拼凑的。

---

## 阅读路径

按推荐顺序：

1. **[git](git.md)** — 最纯粹的内容寻址模型，学完再回头看其他工具的设计，会发现模式是相通的
2. **[nvim](nvim.md)** — 事件驱动的可编程架构，理解插件系统不是「装补丁」而是「挂 hook」
3. **[docker](docker.md)** — 分层文件系统 + 进程隔离的组合拳，一条 `docker run` 背后的完整调用链
4. **[tmux](tmux.md)** — client-server 分离的设计思想，为什么断开 SSH 不会丢会话
5. **[systemctl](systemctl.md)** — Linux 进程生命周期的终极管理者，unit 文件不是配置文件而是声明式状态机
6. **[ssh](ssh.md)** — 加密隧道不只是「安全版 telnet」，它是网络层的瑞士军刀
