# 为什么 find 很强，但 90% 的人只会 `-name`？

<!-- Layer 1: 场景引入 + 功能认知 (Step 1) -->
## 一、你会遇到的场景

某天你收到磁盘告警：根分区使用率 95%。

新手的第一反应往往是 `cd` 进各个目录，挨个 `du -sh *`，一层层往下翻，运气不好的话能翻半小时。更糟的是，有些大文件藏在深处、名字毫无规律，手动翻根本找不到。

而真正理解 find 的人，只会敲一行：

```bash
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

几秒钟之后，所有大于 100MB 的文件列出来，元凶一目了然。

**这就是 find 的核心价值：在文件系统里按任意条件查找文件，并对结果执行操作。** 它不是"搜索文件名"的工具——它是一个文件系统查询引擎。

<!-- Layer 2: IO 模型 (Step 2) -->
## 二、它是怎么工作的——IO 模型

find 的本质不是 `command + options`，而是 `文件树 → 遍历 → 过滤 → 动作 → 结果`：

```
文件系统（从你指定的目录开始）
    │
    ↓ 递归遍历：深度优先，逐个访问每个文件和子目录
    │
    ↓ 按条件过滤：名字对吗？类型对吗？大小对吗？时间对吗？
    │   条件之间默认是 AND 关系——多个条件叠加，范围越来越窄
    │
    ↓ 对匹配的文件执行动作：打印路径 / 删除 / 执行任意命令
    │
输出：执行动作后的结果（默认打印匹配的文件路径）
```

> 💡 理解了 IO 模型，`-type`、`-name`、`-size`、`-mtime`、`-delete` 这些参数就自然出现了——它们分别控制"过滤什么"和"对结果做什么"。每个参数都是在三个处理阶段中的一个上加约束。

<!-- Layer 3: 语法骨架 + 排雷 (Step 3) -->
## 三、语法骨架——先把句型刻进脑子里

```
find  [从哪里开始]  [按什么条件过滤]  [对结果做什么]
      ──┬──         ──────┬──────     ────┬───
      起点槽              条件槽            动作槽
```

属于**骨架模式 A**：`源 → 过滤 → 目标`。三个槽位线性展开，条件可以堆叠任意多个——每一个都是对"我要找什么"的一次精确描述。

⚠️ **在讲具体能力之前，先排一个新手几乎必踩的雷：**

```bash
# ❌ 错误：-exec 忘了分号，语法直接报错
find . -name "*.log" -exec rm {}

# ✅ 正确：\; 是 -exec 动作的结束标志，必须带
find . -name "*.log" -exec rm {} \;
# ⚠️ 以上只是演示语法——实际用 rm 前务必先 -print 确认范围
```

`-exec` 后面跟的是一个要执行的命令。注意：`-exec` **不经过 shell**，它直接调用（exec）指定的程序——`{}` 是匹配文件的占位符（find 会把每个匹配文件的路径替换进去），`\;` 告诉 find"我描述的命令到此结束"。忘了 `\;`，find 不知道你的命令在哪结束。**分号前面加反斜杠是必须的**——不加的话 shell 会把 `;` 当作 shell 命令分隔符吃掉，find 永远看不到它。

> ⚠️ 如果你需要 shell 特性（管道 `|`、重定向 `>`、变量展开等），要用 `-exec sh -c '...'` 包裹，因为 `-exec` 本身不启动 shell。

<!-- Layer 4: 能力轴场景化拆解 (Step 4) -->
## 四、核心能力逐轴拆解

find 的能力沿 7 个轴展开。不要背参数——每个轴回答一个具体问题，各轴正交，自由组合。

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 范围 | 从哪开始找？ | 路径参数（支持多个路径） |
| 类型 | 找文件还是目录？ | `-type f`, `-type d`, `-type l` |
| 名称 | 叫什么？ | `-name`, `-iname`, `-regex` |
| 时间 | 什么时候改的/读的？ | `-mtime`, `-atime`, `-ctime`, `-mmin` |
| 大小 | 多大？ | `-size +100M`, `-size -10k` |
| 权限 | 谁可以读写？ | `-perm`, `-user`, `-group` |
| 动作 | 找到之后做什么？ | `-print`(默认), `-delete`, `-exec` |

---

### 轴 1：类型——"我在找文件还是目录？"

> 场景：你只想清理大文件，但 `du` 的输出混着文件和目录，不好筛选。

```bash
# 只找文件
find /var/log -type f -size +10M

# 只找目录
find /var/log -type d -name "*.old"

# 找符号链接（排查"这个 link 指向的文件还在吗？"）
find /var/log -type l
```

`-type f`（file）限定文件，`-type d`（directory）限定目录，`-type l`（link）限定符号链接。**不加 `-type` 的话，目录也会被包含在结果里**——如果你后面跟了 `-delete`，而一个目录恰好满足条件，整个目录都会被删掉。

---

### 轴 2：名称——"它叫什么？"

> 场景：你记得有个文件叫 "report"，但不记得后缀也不记得目录，还不记得当时用的大小写。

```bash
# 精确匹配（区分大小写）
find . -name "report.pdf"

# 通配符——找所有 .log 文件
find /var/log -name "*.log"

# 忽略大小写——report / Report / REPORT 都匹配
find . -iname "report*"

# 正则表达式——名称以数字开头、.bak 结尾
find . -regex ".*/[0-9].*\.bak"
```

> 💡 `-name` 用的是 shell glob 模式（`*`、`?`、`[]`），不是正则。正则用 `-regex`。而且 `-regex` 匹配的是**完整路径**（包括目录部分），不只文件名。只匹配文件名要用 `-name`。

---

### 轴 3：时间——"什么时候改的/读的/状态变的？"

> 场景：磁盘告警，你想看看是不是最近的日志爆了；或者你想清理 30 天前的旧备份。

```bash
# 最近 7 天内修改过的文件
find /var/log -mtime -7

# 30 天前修改的日志（该清理了）
find /var/log -name "*.log" -mtime +30

# 最近 10 分钟内修改的（"刚才谁动了我的文件？"）
find /etc -mmin -10

# 按分钟：mmin / amin / cmin
find . -mmin -60    # 最近 1 小时改过的
```

符号规则：`+n` = 超过 n，`-n` = 不到 n，`n`(无符号) = 恰好 n。

> 💡 注意精度：`-mtime n` 的定义是"文件数据在 n×24 小时前最后一次修改"，按 24 小时周期向下取整，不是精确到秒的"恰好 n 天前"。比如 `-mtime 1` 匹配的是 24-48 小时前修改的文件，而不是"昨天"。需要分钟级精度用 `-mmin`。

> ⚠️ **ctime 不是"创建时间"！这是 Linux 新手最常见的误解之一。** Linux 大多数文件系统不记录创建时间。`ctime` 是 **inode 变更时间**——权限改了、硬链接数变了、所有者变了都会更新 `ctime`。你真正想找的"文件内容修改时间"是 **mtime**。`atime` 是访问时间（最后一次读），且现代 Linux 通常为了性能会关闭 `atime` 更新。

```bash
# 配合 -ls 看详细信息——确认到底是哪些文件、什么时候改的
find /var/log -mtime +30 -ls
```

---

### 轴 4：大小——"它占了多少空间？"

> 场景：磁盘满了，你怀疑是不是有超大日志文件或 core dump。

```bash
# 大于 100MB 的文件（最常见的"磁盘杀手"排查）
find / -type f -size +100M 2>/dev/null

# 空文件（零字节——可能是错误日志、占位文件）
find . -type f -size 0

# 100MB 到 500MB 之间（精确区间）
find . -type f -size +100M -size -500M
```

符号规则和时间轴一致：`+n` 大于，`-n` 小于。单位：`c`(字节), `k`(KB), `M`(MB), `G`(GB)。不加单位默认是 512 字节块（历史原因），这坑别踩——**始终带单位**。

> ⚠️ `-size` 检查的是文件大小（以块为单位向上取整），不是 `du` 显示的磁盘占用。大多数情况下差异可以忽略，但稀疏文件（sparse file）的 `-size` 会比实际占用大很多。

---

### 轴 5：权限——"谁可以读写它？"

> 场景：安全审计——找出所有"任何人可写"的目录，或者看看自己目录下有没有被改了所有者的文件。

```bash
# 任何人可写的文件（安全风险！）
find /var/www -type f -perm -o=w

# 不属于当前用户的文件
find . -type f ! -user $(whoami)

# 权限恰好等于 777 的文件
find . -type f -perm 777
```

> ⚠️ `-perm` 的参数前缀会改变匹配逻辑：`-perm 777` 是精确匹配，`-perm -777` 是"所有这些权限位都设了"，`-perm /777` 是"这些权限位中任意一个设了"。差一个符号，返回的结果完全不同。

---

### 轴 6：动作——"找到之后做什么？"

> 场景：这是 find 区别于 `locate` 或 `ls | grep` 的关键——find 能对找到的文件**执行操作**。

```bash
# 默认动作：打印路径（-print 通常可以省略）
find . -name "*.log"

# 直接删除（⚠️ 先 -print 确认！）
find /tmp -name "*.tmp" -mtime +7 -print   # 第一步：看看要删什么
find /tmp -name "*.tmp" -mtime +7 -delete  # 第二步：确认无误后执行

# 执行命令——批量压缩 30 天前的日志
# ⚠️ 先 -print 确认范围，再执行
find /var/log -name "*.log" -mtime +30 -print             # 第一步：看看要压缩哪些
find /var/log -name "*.log" -mtime +30 -exec gzip {} \;   # 第二步：确认无误后压缩

# 批量操作（\; vs + 的区别——以安全命令为例）
find . -name "*.log" -exec ls -lh {} \;   # 每找到一个文件执行一次 ls
find . -name "*.log" -exec ls -lh {} +    # 找到一批后批量传给 ls（更快）
```

> 💡 `-exec ... \;` 和 `-exec ... +` 的区别：`\;` 是每个文件单独执行一次命令（慢但灵活），`+` 是把所有匹配文件作为参数一次传给命令（快，但受命令行长度限制）。文件多的时候用 `+` 更高效。

---

### 轴 7：范围——"从哪开始找？"

> 场景：你只想在当前项目里找，不想翻遍整个磁盘；或者你想同时搜索多个目录。

```bash
# 从当前目录开始
find . -name "*.go"

# 同时搜多个目录
find /var/log /opt/app/logs -name "*.log"

# 限制搜索深度（只搜本目录，不递归）
find . -maxdepth 1 -name "*.txt"

# 限制最小深度（跳过根目录本身）
find . -mindepth 2 -name "*.txt"
```

> 💡 `-maxdepth` 和 `-mindepth` 是 GNU 扩展，BSD find 不支持。跨平台脚本可以用 `-path` 条件替代，或者用 `prune` 控制遍历。

<!-- Layer 5: Pipeline 组合 (Step 5) -->
## 五、Pipeline 组合——把命令串起来

Linux 真正强大的地方不是单个 find，而是 find + grep + awk + xargs 的管道组合：

```
find（找到 .log 文件）
    │  输出：文件路径（用 \0 分隔，防空格）
    ↓
xargs -0（把路径传给下一个命令）
    │  输出：grep 的命令行参数
    ↓
grep "ERROR"（从这些文件里找包含 ERROR 的行）
    │  输出：匹配的文本行
    ↓
wc -l（数有多少行 → ERROR 总数）
```

```bash
find /var/log -name "*.log" -mtime -7 -print0 | xargs -0 grep "ERROR" | wc -l
```

> 💡 这里能串起来的关键是：`find -print0` 输出 `\0` 分隔的路径，恰好是 `xargs -0` 期望的输入格式。`xargs` 把路径转化为 `grep` 的参数，`grep` 输出到 stdout，`wc -l` 从 stdin 读取。**每一个连接点的 IO 格式都是匹配的**。理解 IO 模型之后，管道组合就是搭积木。

<!-- Layer 6: 真实排障复盘 (Step 5) -->
## 六、真实排障全流程复盘——磁盘告警

回到开头那个磁盘告警的场景，完整走一遍：

**第一步：定位——找出系统中的"空间大户"**
```bash
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```
- 范围轴：`/`（全盘搜索）
- 类型轴：`-type f`（只看文件）
- 大小轴：`-size +100M`
- 动作轴：`-exec ls -lh`（显示大小和路径）
- `2>/dev/null`：权限不足的目录报错直接忽略

**第二步：聚焦——确认是不是 /var/log 下的日志在失控增长**
```bash
find /var/log -type f -size +10M -ls
```
缩小范围到 `/var/log`，降低阈值到 10MB，用 `-ls` 看详细信息（大小、权限、时间）。

**第三步：预览——在动手删之前看看有哪些**
```bash
find /var/log -name "*.log" -mtime +30 -print
```
⚠️ 安全铁律：先 `-print` 确认，再加 `-delete`。`+30` 是"超过 30 天"——这些通常是安全的清理目标。

**第四步：执行——删除 30 天前的旧日志**
```bash
find /var/log -name "*.log" -mtime +30 -delete
```

**第五步：复查——磁盘回来了吗？**
```bash
df -h /
```

> 整个过程没有手动进任何一个目录，没有 `ls` + 肉眼比对，全程靠 find 的条件组合完成定位→聚焦→预览→执行→复查。

<!-- Layer 7: 踩坑 + 边界 + 迁移 -->
## 七、踩坑清单

- **坑一：ctime ≠ 创建时间** → 文件内容修改看 mtime，inode 变更才看 ctime
- **坑二：-exec 忘了 `\;` 直接报错** → `\;` 是 -exec 的结束标志，不是"随手的习惯"
- **坑三：-delete 前不确认** → 先用 `-print` 或 `-ls` 看一眼，铁律不能忘
- **坑四：不加 `-type f` 误操作目录** → 目录也匹配条件时，`-delete` 会把整个目录删掉
- **坑五：`-size` 不带单位** → 默认是 512 字节块，数字完全不对。始终带单位（k/M/G）
- **坑六：`-name` 用正则** → `-name` 是 shell glob（`*.log`），正则用 `-regex`
- **坑七：`-perm 777` vs `-perm -777` vs `-perm /777`** → 精确匹配/全都设了/任意一个设了，差之毫厘

## 八、什么时候该换工具

find 不是万能的。

| 场景 | 用什么 | 为什么 |
|------|--------|--------|
| 按文件名快速查找 | `locate` | 数据库查询，比 find 快百倍（需要 `updatedb`） |
| 搜索文件内容 | `grep -r` | 搜文件名用 find，搜内容用 grep |
| 看某目录的磁盘占用 | `du -sh` | find 不擅长做加和统计 |
| 实时监控文件变化 | `inotifywait` | find 是快照式查找，不是持续监控 |
| 批量重命名 | `rename` / `mmv` | find + exec mv 可以但不够优雅 |

## 九、换个命令你会了吗？

find 属于**骨架模式 A**：`源 → 过滤 → 目标`。同一模式的命令还有：

- **rsync**：同步文件的"源 → 过滤 → 目标"——指定源路径、包含/排除规则、目标路径，和 find 的句型完全一致
- **locate**：在文件名数据库中查找——更快但功能更少，本质上也是"从哪找 → 怎么过滤 → 输出结果"

学完 find，你其实已经掌握了"源→过滤→目标"这一类命令的语法骨架。**下次遇到 rsync，先问自己：源是什么？过滤条件有哪些？目标是什么？** 这三个问题答上来，命令自然就出来了。

> **核心观点：** 学 find 不是为了记住 `-name -mtime -size -delete` 这些字母，而是理解它的 **IO 模型**（文件树 → 遍历 → 过滤 → 动作）和 **7 个能力轴**（范围、类型、名称、时间、大小、权限、动作）。一旦这两个立住了，任何"找文件"的需求你都能从轴里选出组合，填入骨架，命令自然生成。
