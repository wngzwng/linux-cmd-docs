# 五步认知模型详解

> 来自 `linux-cmd-thinking`。这是整个教程的**认知骨架**——写教程前，先用这五步把自己对命令的理解结构化。

---

## 前置心态：别背参数，先构造查询

大多数新手学命令时的问法是错的。不是问「后面应该加什么参数」，而是问：

> 我现在要查的**对象**是什么？我想看它的哪个**维度**？要按什么**条件**过滤？输出里带哪些**信息**？

比如你敲 `ss -tulnp`，你并不是在「使用一个网络命令」。你是在问系统：

> 当前机器有哪些网络 socket？哪些端口正在监听？8080 是不是已经被占了？这个端口背后是哪个进程？我想看数字端口号，还是服务名？

这样一换，`-tulnp` 就不再是五个需要硬背的字母，而是**五个独立的筛选条件**：

| 字母 | 含义 | 你要问的问题 |
|------|------|-------------|
| `-t` | TCP | 只看 TCP socket？ |
| `-u` | UDP | 还要看 UDP？ |
| `-l` | listening | 只看正在监听的？ |
| `-n` | numeric | 端口用数字（不解析成服务名）？ |
| `-p` | process | 告诉我背后是哪个进程？ |

命令的本质不是背诵语法，而是**构造查询**：`工具 + 条件 + 对象`。

## 第 1 步：功能认知——这个命令解决什么问题

**用一句话说清楚。** 如果你不能用一句话说清楚，说明这步没到位。

- **find：** 在文件树里查找满足条件的文件，并对结果进行处理
- **tar：** 把一堆文件捆成一个归档，可选压缩
- **grep：** 从文本流或文件中筛选匹配某种模式的内容
- **ss：** 查看当前机器的 socket 统计信息——谁在监听哪个端口、连接状态是什么
- **lsof：** 列出进程打开的文件/资源——哪个进程打开了哪些文件、socket、管道

> 💡 命令名本身就是线索：`ss` = **s**ocket **s**tatistics，`lsof` = **l**i**s**t **o**pen **f**iles，`ps` = **p**rocess **s**tatus，`grep` = **g**lobal **r**egular **e**xpression **p**rint。知道全称之后，"为什么 lsof 能查端口"这种困惑自然消解——因为网络 socket 在 Linux 里也是通过文件描述符来管理的。

## 第 2 步：IO 模型——输入是什么，输出是什么

**Linux 命令的本质不是 `command + options`，而是 `Input → Transform → Output`。** 理解输入输出，比记参数更重要。

### 两种 IO 范式

#### 范式一：数据处理型（Input → Transform → Output）

大多数命令属于这类——接受数据，变换，输出结果。

| 命令 | 输入 | 变换 | 输出 |
|------|------|------|------|
| find | 文件系统目录树 | 遍历 → 过滤 → 动作 | 匹配的文件集合 |
| grep | 文本（文件/stdin/pipe） | 模式匹配 → 筛选 | 匹配行/文件名/计数 |
| tar | 文件集合（目录/文件） | 归档 → 压缩（可选） | archive 文件 |
| ss | 内核 socket 表 | 按协议/状态筛选 → 格式化 | socket 列表 |
| lsof | 内核打开文件表 | 按类型/进程筛选 → 格式化 | 打开文件列表 |

#### 范式二：状态管理型（Current State → Desired State → Action）

像 `systemctl start nginx`、`docker restart`、`kubectl apply` 这类命令，处理的是系统状态而非数据流。你描述目标状态，命令负责把当前状态变成目标状态。

而且这类命令背后通常有一个**对象层级**。比如 tmux：`server → session → window → pane`。不理解这个，`tmux send-keys -t dev:0.1` 里 `dev:0.1` 就是一行天书。理解了，`session:window.pane` 就是三个坐标。

> **写教程的关键判断：** 先确认命令属于哪种范式。数据工具关心「数据如何流动」，系统工具关心「对象如何存在、变化、销毁」。范式不同，IO 模型的表述方式不同。

## 第 3 步：语法骨架——先把「句型」刻进脑子里

每个命令有一个固定的**句型结构**，就像英语里有「主语 + 谓语 + 宾语」。

### 五种骨架模式

| 模式 | 句型 | 代表命令 | 本质 |
|------|------|---------|------|
| **A. 源 → 过滤 → 目标** | `命令 起点 条件 动作` | find, rsync | 在集合中筛选+操作 |
| **B. 模式 + 对象** | `命令 选项 核心参数 操作对象` | grep, sed, tar, sort | 对对象按模式处理 |
| **C. 动作 + 目标** | `命令 动作标志 目标` | kill, systemctl, rm, chmod | 告诉系统对谁做什么 |
| **D. 查询 + 展示** | `命令 查询对象 + 维度 + 格式` | ps, top, df, du, free | 查看系统状态 |
| **E. 输入 → 转换 → 输出** | `命令 输入 → 规则 → 输出` | sed, awk, cut, sort, uniq, jq | 文本流处理 |

### 具体示例

```
find  [从哪里开始]  [按什么条件过滤]  [对结果做什么]         ← A 类
tar   [动作+压缩模式]  -f  [归档文件名]  [操作对象...]       ← B 类
grep  [选项]  [模式]  [文件...]                            ← B 类
ss    [协议/状态/格式选项]  [过滤表达式]                    ← D 类
kill  [信号]  [PID]                                        ← C 类
```

> **教程中的价值：** 同一骨架模式的命令，学了一个就能迁移到另一个。在教程末尾做"迁移提示"，读者会豁然开朗。

## 第 4 步：能力轴展开——参数沿哪些方向展开

**不要再背参数表。要问的是：这个命令的能力沿着哪几个轴展开？** 每个轴回答一个具体问题，各轴之间正交，自由组合。

### 能力轴表格式

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| ... | 这个轴回答什么问题？ | 该轴下有哪些选择 |

### 示例：find 的能力轴

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 范围 | 从哪开始找？ | 路径参数 |
| 类型 | 找文件还是目录？ | `-type f`, `-type d`, `-type l` |
| 名称 | 叫什么？ | `-name`, `-iname`, `-regex` |
| 时间 | 什么时候改的/读的？ | `-mtime`, `-atime`, `-ctime`, `-mmin` |
| 大小 | 多大？ | `-size +100M`, `-size -10k` |
| 权限 | 谁可以读写？ | `-perm`, `-user`, `-group` |
| 动作 | 找到之后做什么？ | `-print`, `-delete`, `-exec` |

### 示例：ss 的能力轴

| 能力轴 | 问题 | 选项 |
|--------|------|------|
| 协议 | TCP 还是 UDP？ | `-t`(TCP), `-u`(UDP), 不加=默认仅 TCP（非全部协议） |
| 状态 | 监听中还是已建立？ | `-l`(监听), `-a`(全部状态) |
| 显示格式 | 数字还是服务名？ | `-n`(数字端口号), `-r`(反解主机名) |
| 进程 | 背后是哪个进程？ | `-p`(显示进程信息，常需 sudo) |
| 过滤 | 只要某个端口？ | `'sport = :8080'`, `'dport = :443'` |

> **教程中的价值：** 能力轴表替代了传统的"参数列表"。读者不需要记住 20 个参数，只需要记住 5 个能力方向和每个方向上的 2-3 个选项。脑容量需求从 O(n) 降到 O(log n)。

## 第 5 步：场景组合——从需求反推

面对具体场景时，思考过程：

```
需求 → 这个需求属于哪个命令的功能范围？（第 1 步）
     → 输入是什么，输出要什么？（第 2 步）
     → 需要用到哪几个能力轴？（第 4 步）
     → 每个轴选哪个值？（第 4 步）
     → 按什么顺序填入骨架？（第 3 步）
```

### 示例：「找出 /var/log 下 7 天前的、大于 10MB 的日志文件，删掉」

```
第 1 步：找文件 + 对结果操作 → find
第 2 步：输入=/var/log，输出=被删除的文件
第 4 步选能力轴：
  - 范围：/var/log
  - 名称：*.log
  - 时间：7 天前 → -mtime +7
  - 大小：大于 10MB → -size +10M
  - 动作：删除 → -delete
第 3 步填入骨架：
  find  [/var/log]  [-name "*.log"]  [-mtime +7]  [-size +10M]  [-delete]

⚠️ 安全铁律——先预览，再执行：
→ find /var/log -name "*.log" -mtime +7 -size +10M -print  # 第一步：确认范围
→ find /var/log -name "*.log" -mtime +7 -size +10M -delete # 第二步：确认无误后执行
```

## Pipeline 思维

单个命令只是积木。Unix 的核心理念：**小工具解决小问题，通过管道组合出复杂能力。**

```
Command A  →  Command B  →  Command C
  解决一个    解决一个    解决一个
  局部问题    局部问题    局部问题
```

### Pipeline 的核心思维

```
一个命令解决一个局部问题
多个命令通过管道形成流水线
每个命令的输出恰好是下一个命令的输入
```

### 示例：「统计最近 7 天日志中的 ERROR 数量」

```bash
find /var/log -mtime -7 -type f | xargs grep "ERROR" | wc -l
# 💡 生产环境建议加 -print0 / -0 防止文件名含空格导致 xargs 切分错误
```

这里能串起来的关键：
- `find` 输出文件路径列表
- `xargs` 接受路径列表，传给 `grep`
- `grep` 输出匹配行
- `wc -l` 接受文本行，输出计数

**IO 模型的匹配是管道能工作的前提。**

## 最容易犯的句型错误

```bash
# ❌ tar 的 -f 跟了别的选项。 -f 是带参数选项，后面必须紧跟文件名
tar -cfv archive.tar dir/

# ❌ find 的 -exec 忘了 \;，语法直接报错
find . -name "*.log" -exec rm {}

# ❌ 不推荐：grep 的 options 放在 pattern 后面（虽然 GNU grep 允许，但不符合语法骨架）
grep "error" -r -i /var/log
grep -r -i "error" /var/log    # ✅ 推荐：options → pattern → files
```

## 忘了参数怎么办：先看本机帮助，别先搜索

```bash
command --help       # 快速查阅
man command          # 完整手册

# 在 man 页面里：/关键词 搜索，n 下一个，q 退出
```

常用英文关键词：list, show, process, file, socket, listen, numeric, recursive, filter, exclude

> 💡 排障命令速查：查端口和连接→`ss`，查进程打开了什么→`lsof`，查进程状态→`ps`，查文件→`find`，查文本→`grep`。工具可以换，目标不变。
