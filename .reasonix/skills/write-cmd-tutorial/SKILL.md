# Linux 命令教程写作

## 风格说明

这种风格的核心是 **"不教命令，教排障思路"**。读者不是为了背选项来看的，是为了"下次遇到这个问题知道怎么解决"。

遵循以下结构模板，按需调整顺序和篇幅。

---

## 标准段落结构

### 第 0 层：文章钩子（标题 + 开头）

标题用一个"反差"制造好奇：

> 为什么 X 很强，但很多人一直不会用？

开头点出现象：

> 很多人用了好几年 Linux，X 永远只会一种用法——xxx，再复杂一点就直接放弃。其实 X 真正的威力，远不止 xxx 这么简单。

### 第 1 层：场景引入（先摆问题，再给答案）

**不用**："X 命令用于查找文件。"

**要用**：

> 某天你收到磁盘告警：根分区使用率 95%。
>
> 新手的第一反应往往是 cd 进各个目录，挨个 du -sh *，一层层往下翻，运气不好的话能翻半小时。
>
> 而真正熟悉 X 的人，只会敲一行：...
>
> 几秒钟之后，所有结果列出来，元凶一目了然。

关键要素：
- **真实场景**：读者可能遇到过的实际问题
- **新手做法**：笨的、慢的、错的做法（制造"我好像也是这样的"共鸣）
- **正确做法**：一行命令干净解决
- **反差感**：新手半小时 vs 老手几秒钟

### 第 2 层：核心概念（一句话说清楚它是什么）

> X 的核心逻辑只有一句话：从某个目录开始，遍历...按条件挑出...

如果有容易混淆的命令，做**对比区分**：

> 听起来和 Y 有点像，但本质完全不同：**X 做的是 A，Y 做的是 B。** 这也是为什么排障时它们经常组合使用，而不是互相替代。

### 第 3 层：先排雷（最容易踩的坑）

> 在讲具体能力之前，必须先讲一个新手几乎一定会踩的坑。

选一个最常见、后果最严重的错误，用 ❌ ✅ 对比：

```bash
# ❌ 错误的写法
X xxx

# ✅ 正确写法
X xxx
```

解释**为什么**错（Shell 展开机制、默认行为误解等）。

### 第 4 层：核心能力逐个拆解（点状教学）

每讲一个能力，结构是：

```
#### 1. 按 XX 找

场景/说明：

```bash
命令示例
```

关键细节（如果有 +- 符号的含义、容易搞混的点）：

```bash
进阶组合用法
```

⚠️ 纠正常见误解（如果有）：
> **ctime 不是'创建时间'，而是...**
```

注意事项：
- 每个选项讲清楚**什么时候用**，不是罗列参数
- 纠正流传很广的误解（加粗强调）
- 给出对比：低效写法 vs 高效写法
- 对于 destructive 操作，**安全建议前置**：先 dry-run 确认

### 第 5 层：组合用法（把点连成线）

> 如果你不光想知道 A，还想 B，可以配合 Y：

```bash
X ... | Y ...
```

解释这条组合里**每个命令负责什么**。

### 第 6 层：真实排障流程（完整复盘）

回到开头的场景，完整走一遍：

```
第一步：xxx（定位）
第二步：xxx（确认）
第三步：xxx（先 print 不要直接删）
第四步：xxx（执行）
第五步：xxx（复查）
```

> 整个过程没有手动进任何一个目录，全程靠 Y 的条件组合完成定位、确认、清理三个阶段。

### 第 7 层：新手踩坑总结

按列表总结所有提到的坑，每条一行：

- 坑一：xxx → 正确做法是 xxx
- 坑二：xxx → 记得用 xxx

### 第 8 层：面试题（可选）

给出一个实际面试题，解析它考察了哪几个知识点。

### 第 9 层：什么时候换工具

> X 不是万能的，...如果你只是想 Y，用 Z 通常更快。

诚实给出工具边界，推荐替代方案及其适用场景。

### 第 10 层：结尾

总结核心观点，用"你平时..."收尾，引发读者思考。

## 写作原则

### 1. 每条命令至少有一个场景

没有场景的命令不写。读者需要知道"什么情况下用这个"。

### 2. 每条 destructive 操作前先教安全习惯

> 任何带 -exec rm 或者 -delete 的命令，第一次执行前，先把删除动作换成 -print，确认列出来的文件确实是你想删的，再加回删除动作。

### 3. 纠正一个流传很广的误解

每个教程至少纠正一个常见认知错误。用 **加粗 + 不是...而是...** 句式。

### 4. 给对比

- 新手 vs 老手
- 错的 vs 对的
- 低效 vs 高效
- 场景A用这个，场景B用那个

### 5. 用"你"直接对话

全文用第二人称，像面对面教学。

### 6. 💡 / ⚠️ 标记

- `💡` 小贴士：容易被忽略但很有用的细节
- `⚠️` 警告：可能出错或造成损失的地方
